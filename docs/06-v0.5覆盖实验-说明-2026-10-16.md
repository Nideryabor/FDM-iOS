## 一、业务实验的原理

安卓版思路：往 MMKV 写 `kv_settings_<key>` 覆盖服务端值。

iOS 版架构不同 —— 服务端设置**整套压成一个 blob**：
```
MMKV 实例 : mmkv.default
键        : app.ab.serverValues
值        : 一个「双层 JSON」
            外层 = JSON 字符串字面量：  "{\"version\":93,...}"
            内层 = 真正的设置对象：      {"version":93,"settings":{<key>:{"id":N,"value":V}}}
```

**我们的做法**：Hook 这一个键的**读 + 写**：
```
应用写入 serverValues  →  我们抓下来 → 改掉指定项的 value → 存回改过的版本
应用读取 serverValues  →  直接给它改过的版本
```

⇒ 效果上等价于安卓的"本地覆盖层"，但操作对象是 blob 而非单键。

## 三、安全设计（吸取 v0.2/v0.3 崩溃教训）

| 铁律 | 做法 |
|---|---|
| Hook 内不调宿主方法 | 只 `strcmp` 比对 key（且先查 `isKindOfClass`） |
| Hook 内不做文件 IO | 只加计数 + 内存缓冲；后台每 2 秒刷盘 |
| 重入保护 | `__thread int gDepth` |
| 只对目标键动手 | `strcmp(key, "app.ab.serverValues") == 0`，其余原样放行 |
| 只改 value | blob 里**其余字段一字不动**，结构完全保留 |
| 解析失败就放弃 | `PatchBlob` 返回 nil ⇒ 原样透传，绝不写坏数据 |

## 五、判读表

| 现象 | 含义 | 下一步 |
|---|---|---|
| `fdm3-images.txt` 里 TweakInject = 0 | ✅ **Choicy 生效** | 继续 |
| TweakInject 仍 13 个 | ⚠️ Choicy 没生效/被顶掉 | 尼尼换招 |
| `hits.txt` 写=0 读=0 | 这个键**这次没被碰** | 让 App 多跑一会儿 / 切设置页 |
| 写>0 但 patch failed>0 | blob 结构变了 | 尼尼重新分析 |
| 写>0 且 mod 文件生成 | ✅ **覆盖成功注入** | **看 UI 有没有变化** |
| **UI 出现了变化** | 🎉 **业务实验成功！** | 可以开始做正式功能 |
| UI 无变化但 hits 正常 | 宿主有内存缓存，没重读 | 改 Hook `RemoteSettingsManager.localSettingsGetter` |
