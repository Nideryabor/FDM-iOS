## 一、富文本复发：指纹判据错了（真 bug）

### 症状

主人报「又抽风裸标签」。日志：

```
13:19:32  [ensure] ★ 巡检修正 … 325→265 字     ← 只修了一次
13:19:33  [rich] ★ 裸标签渲染 383 → 371 字
（之后巡检再没动静，屏幕一直裸着）
```

### 病根

v78 的巡检里，指纹记的是**原串**：

```objc
NSString *str = cur.string;                       // 当前（裸标签）
NSString *prev = [gEnsuredFP objectForKey:v];     // 上次记的
if (prev && [prev isEqualToString:str]) continue; // ← 错误判据
...
[gEnsuredFP setObject:str forKey:v];              // 记的也是原串
```

宿主把渲染好的又打回原样后：

1. 当前串 **又变回原串**
2. 巡检一看「这个串我修过呀」⇒ `continue` 跳过
3. ⇒ **永远放手，只修一次**

### 修法：比「目标状态」而不是「我干过没」

```objc
// 记的是**我设进去的结果串**
[gEnsuredFP setObject:rich.string forKey:v];

// 判据：当前 == 我上次设的结果 ⇒ 对，跳过
//       当前 != 结果           ⇒ 被打回了 / 内容变了 ⇒ 修
if (prev && [prev isEqualToString:str]) continue;
```

只要屏幕不是我要的样子，就说明被打回了 ⇒ 再修一次。
**这才是「状态驱动」的本意。**

### 顺带改掉的两处

| 改动 | 原样 | 现在 | 为什么 |
|---|---|---|---|
| 去掉「含 `<` 才处理」的快闸 | `if (rangeOfString:@"<" == NSNotFound) continue;` | 删掉，改为「!= 目标就修」 | 渲染后的内容**可能仍含 `<`**（用户真想显示 `<b>` 字面量），旧闸门会误跳过 |
| 渲染器说「没啥可渲染」时也记账 | 直接 `continue`（每轮白跑 render） | `[gEnsuredFP setObject:str]` | 性能：避免每 0.4s 重跑一次 |
| 新增防抖 | 无 | 同控件 1.5s 内最多修 6 次 | 宿主若死命覆盖，不至于打满 CPU |

### 真机验证（关键证据：**同一控件反复修**）

```
13:33:37.339  [ensure] ★ 巡检修正 … 144 → 123 字
13:33:41.474  [ensure] ★ 巡检修正 … 144 → 123 字    ← 又被打回
13:33:42.927  [rich]   ★ 裸标签渲染 144 → 123 字
13:33:41.475  [ensure] 本轮修正 1 个控件（累计 15）
```

`144→123` 反复出现 ⇒ 宿主确实在持续打回，巡检也确实在持续纠正。
**旧版在这里只会有第一条，之后永远沉默。**

> ⚠️ 剩下的问题：宿主每帧都在打回，我们每轮都在修 —— 这是「打地鼠」。
> 真正根治要在宿主绘制层，成本很高。当前策略（打地鼠 + 防抖）**能用**，
> 先保证不出裸标签。

## 二、AI 点歌：链路上唯一缺的那环

### 体检结论

点歌的**渲染 / 播放 / 去重**早就写好了（`FDMRichText.m` 的 `RenderDj` +
`FDMMusicPlayByKeyword`），快速闸三处也齐（定界符 / `FDMRichMaybeAffected` /
kind 判定）。**唯独没有任何东西告诉模型这个标记存在** ⇒ 模型永不写 ⇒
功能等于不存在。

### 修法：拼进系统提示词

注入链路只有一条（`⟦FDM⟧ … ⟦/FDM⟧`，显示层由 `FDMStrip` 抹掉），
所以直接拼在 `FDMInjectConfig()` 返回的文本末尾 —— **零新增通道、零新增 hook**。

新增 `FDMDjPromptFragment()`（`FDMFeatures.m`）：

```
【点歌】
这个 App 接了网易云播放器，你可以替用户放歌。方法：在回复里另起一行，
只写一个标记，形如：
⟦DJ:歌名-歌手⟧
例：⟦DJ:晴天-周杰伦⟧
规则：
· 这一行除了标记什么都不要写，标记前后都不要有别的字
· 标记会被 App 吃掉并显示成播放状态，用户看不到它本身
· 不需要解释你在放歌，App 会自己显示
· 一次回复最多点一首；不确定歌名时用你最有把握的那个
· 如果不想让对话里留下「正在播放」那一行痕迹，写成 ⟦DJ:歌名-歌手|hidden⟧
· 用户明确要求听歌、或聊到音乐时才用；别每句都点
```

### 措辞上的三个坑

| 坑 | 处理 |
|---|---|
| 模型爱写成「正在为你播放《晴天》 ⟦DJ:…⟧」 | 明写「这一行除了标记什么都不要写」「不需要解释」 |
| 我第一版说明里用了 markdown 加粗 | iOS 设置页不渲染 markdown，显示成字面星号 ⇒ 全项目 16 处 `**` 一起清掉 |
| 半角/全角冒号 | `⟦DJ:` 必须是**半角 U+003A**，已用 python 逐字节核对 11 处标记 |

### 三个新开关（音乐页）

| 字段 | 默认 | 作用 |
|---|---|---|
| `dj_prompt_on` | 开 | 让 AI 知道可以点歌 |
| `dj_prompt_text` | 空 | 自定义说明（留空用内置） |
| `dj_inline_hint` | 开 | 渲染时显示「♪ 正在给你放：xxx」；关掉 = 整段消失 |

### 真机验证

```
13:31:39.787 [I][inject] [dj] 点歌说明已拼进系统提示词（261 字，模式=fdm）
13:31:39.785 [I][cfg] 功能注册完成：26 页 / 266 项     ← 从 260 到 266
```

### ★★ 端到端实锤（最重要的一条）

```
13:33:42.741 [D][music] [dj] 红色高跟鞋-蔡健雅 15 秒内处理过，跳过   ← 去重在工作
```

## 三、顺手加的两个工具能力

### 3.1 `ui_auto_shot` 支持「滚到底补拍」

设置页经常比一屏长，只拍首屏会漏掉页尾 —— 这次加的三个字段就全在「说明」区之后，
第一张截图根本看不到。

新增 `FDMUIAutoShotCaptureTail()`：找当前页的 tableView，滚到最后一行，
0.35s 后拍一张 `*-tail.png`。

### 3.2 `tools/alive.sh` —— 别再拿进程数判崩溃

**这是我今天犯的错**：看到 `ps | wc -l` = 0，判定「App 崩了」，还回滚了版本。
真相是**设备息屏**，App 被系统挂起。

工具按顺序给四个判据，并明确说「没有崩溃日志就基本不是崩」：

```
── 1 进程 ──            进程数: 0
── 2 最近 30 分钟崩溃 ── 无（这条最重要）
── 3 屏幕锁定状态 ──
── 4 日志末行时间 ──
=> 判定：大概率是息屏/被系统回收，不是崩溃。
```

## 五、教训（加进铁律）

39. **指纹要记「目标状态」，不是「我干过没」。**
    v78 记原串 ⇒ 被打回后永远放手。状态驱动的判据必须是
    「当前 == 我想要的样子吗」，不是「这个对象我处理过吗」。

40. **`ps | wc -l` = 0 不等于崩溃。**
    先看有没有**新的**崩溃日志。息屏 / 被系统回收都是 0，而它们不出崩溃日志。
    差点因为误判回滚一个没问题的版本。

41. **iOS 二进制里中文是 UTF-16LE。**
    `strings` 只抓 ASCII，`grep` 搜 UTF-8 也是 0 命中。
    验证字符串进没进产物要用 python 搜 `.encode('utf-16-le')`。

42. **设置页说明别写 markdown。**
    加粗语法在 iOS 设置页会显示成字面星号（那是给文档用的，不是给 UI 用的）。
