放纯 C 里 47 条断言一跑，这类怀疑直接消失。

## 二、与安卓最大的结构差异

| | 安卓 | iOS |
|---|---|---|
| 播放器跑在哪 | **模块自己的进程**（`MusicService`） | 宿主进程内 |
| 迷你卡怎么拿到状态 | 跨进程广播（`ACTION_STATE` / `ACTION_CMD`） | 直接读全局队列 |
| 宿主被杀 | 播放继续（独立进程） | 停播 |

⇒ iOS 省掉了 `FdmPush`/广播这一整套，代码短很多；代价是跟宿主同生共死。

## 三、四个设计决定（都写了理由在代码里）

### 3.1 音频会话只设一次，永不"恢复"

```objc
// 只在第一次播放时设 playback，之后永不改也永不恢复
[s setCategory:AVAudioSessionCategoryPlayback error:&e];
```

宿主自己有语音输入 / TTS，会在它需要录音时把 category 改成 `playAndRecord`。
我们**不能**去抢，也不能在播完后"恢复"成原来的 —— 恢复动作本身就会打断它。
**宿主自己会覆盖成它要的**，这是最不打扰的姿势。

### 3.2 存档只在拐点上写

切歌 / 暂停 / 退出 才写 `state.json`；播放中靠 30 秒一拍兜底。
（安卓那边每秒写盘踩过发热 + 卡顿）

### 3.3 重启后 state 一律变 PAUSED

```objc
q->state = FDMMS_PAUSED;   /* 重启不该自动出声 */
```

### 3.4 「下一首」的真值表（这次真抓到 bug）

| repeat | 手动点「下一首」 | 一首放完自动接 |
|---|---|---|
| OFF | 还有就下一首，尾巴上停 | 同左 |
| ALL | 绕回第 0 首 | 绕回第 0 首 |
| **ONE** | **跳到下一首**（用户想换歌） | **原地重放** |

第一版实现漏了「ONE + 手动 + 在最后一首」这一格 —— 真值表第 10 条断言当场抓住。
Android 版也是这么定的（单曲循环下点下一首必须换歌，否则按钮像坏的）。

## 四、点歌（⟦DJ:…⟧）—— 加标记族要改三处

安卓 3.69.4 的血案：只改了两处，**渲染前的快速闸漏了 DJ 族** ⇒
模型写了标记但永远不触发，查了很久。

iOS 这次一口气全改：

| # | 位置 | 改了什么 |
|---|---|---|
| ① | `FDMRichText.m` 定界符区 | `kDjOpen` = `⟦DJ:` / `kDjClose` = `⟧` |
| ② | `FDMRichMaybeAffected` | 加一行 `if ([s rangeOfString:kDjOpen]...) return YES;` |
| ③ | 主扫描循环 | 新增 `kind == 4` 分支 + `NSRange rd` |

**去重 15 秒窗**：渲染层对同一条消息会调很多次（cell 复用 / 滚动 / 流式每帧），
不去重就是「一首歌被点 20 次」。照抄安卓 `DEDUP_MS = 15s`。

隐藏写法：`⟦DJ:晴天-周杰伦|hidden⟧` —— 只放歌，气泡里什么都不显示。

## 五、{music} / {lyric} 终于有数了

v63 的状况：`FDMPromptVars.c` 引擎 20 条断言全过、`FDMProbeReadDebugBool` 读得到开关、
`FDMProbe.m:861` 也接了发消息时的替换 —— **但 provider 是空的**，
所以 `{music}` 永远替换成空串。

v64 补的是「快照 + 注册」：

```objc
static NSDictionary *gSnap = nil;          /* 只在主线程更新，不可变 */

static void MusicUpdateSnapshot(void) {
    // song / artist / album / pos / dur / playing / lyric / lyric_prev / lyric_next
    gSnap = [d copy];
}

/* Install 里 */
FDMPromptVarsSetProvider(^NSDictionary *(void) { return gSnap ?: @{}; });
```

**为什么用快照而不是让 provider 直接读队列**：provider 在「发消息那一刻」被调，
那是网络 hook 线程；而队列只在主线程改。快照是不可变字典，读的人既不用加锁
也不会读到半个状态。

## 六、这一轮踩的坑

| # | 坑 | 教训 |
|---|---|---|
| 1 | `[[NSURLSession sharedSession] dataTaskWithURL:...].resume;` | clang 报 `-Wunused-getter-return-value`（Theos 当 error 处理）。要先接住 task 再 `[task resume]` |
| 2 | `[player replaceCurrentItemWithPlayerItem:nil]` | 参数是 `nonnull`，编译期就报错。停播直接 `gPlayer = nil` 让 ARC 收尸 |
| 3 | `dispatch_async` block 里给外部变量赋值 | 必须 `__block`；这次改成用局部变量重算，绕开了 |
| 4 | 通知用 `removeObserver:nil name:...` | 不能这么拆。要留 token：`gEndObs = [[NSNotificationCenter defaultCenter] addObserverForName:...]` |
| 5 | 单曲循环 + 手动 + 尾巴 | 真值表第 10 条断言抓到（见 §3.4） |
| 6 | **`source env.sh` 之后再跑 `tests/run-all.sh`** | 7 套全"编译失败" —— PATH 里有 iOS 的 `ld64.lld`，`gcc` 链接时用了它，报 `unknown argument '-plugin'`。**跑测试必须在干净 shell** |
| 7 | `make` 说 `Nothing to be done` 但产物是旧的 | 铁律 12 的现场版。靠 `touch` + 核对 mtime + `llvm-nm` 查符号三重确认 |
| 8 | `strings dylib \| grep 音乐播放` = 0 命中 | 中文 ObjC 字面量进 `__TEXT,__ustring`（UTF-16），`strings` 默认只扫 ASCII。**验证要靠符号表**（`llvm-nm` 查 `_FDMMusicInstall`） |

## 八、真机待验清单（设备一连上就按这个跑）

1. `echo '{"on":true,"mini_on":true}' > Documents/fdm-music.json` ⇒ 重启 ⇒ 迷你卡出现
2. 点 ♪ ⇒ 输入「晴天」⇒ 回车 ⇒ 点第一条 ⇒ **出声 + 封面 + 歌词**
3. 拖动卡片 ⇒ 杀 App 重开 ⇒ **位置记住**
4. 播完一首 ⇒ 自动接下一首（看日志 `[music] 一首放完了`）
5. 切循环到 ↻1 ⇒ 等一首放完 ⇒ **原地重放**；点 ▶▶ ⇒ **换歌**
6. 模型写 `⟦DJ:稻香-周杰伦⟧` ⇒ 气泡显示「♪ 正在给你放：稻香-周杰伦」+ 开播
7. `pvar_on=true` + 系统提示词里写 `{music}` ⇒ 发一条 ⇒ 服务端收到的是真歌名
8. 宿主语音输入仍可用（**音频会话没被打哑**）← 最重要的回归项

## 九、给下次的三句话

> **1. 纯逻辑先抽出来。**
> 900 行 C + 47 条断言，换来真机上不用怀疑「是不是我切歌算错了」。

> **2. `source env.sh` 会污染 gcc。**
> 跑离线测试前先确认 PATH 里没有 iOS 交叉工具，否则 7 套全部"编译失败"，
> 而且报的错跟测试本身一点关系都没有（`ld64.lld: unknown argument '-plugin'`）。

> **3. 中文 ObjC 字面量在 `__ustring`，`strings` 看不见。**
> 想自证「改动进产物了」，查符号（`llvm-nm`）或查类名（`strings` 找 ASCII 的类名），
> 别查中文。
