### 2.2 P2 · AI 气泡富文本 ✅ 一次通

真机验证：主人看到**彩色 / 粗体 / 带框卡片**。

```
⟦FDM:hi|名字⟧            → 亮色粗体
⟦FDM:warn|内容⟧          → 黄底黑字
⟦FDM:card|标题|内容⟧     → 带框卡片（<br> 换行）
⟦FDM⟧<b>粗</b><c6>蓝</c>⟦/FDM⟧  → 匿名包裹
```

**支持标签**：`<b> <i> <u> <s>/<del> <br> <c1-9> <bg1-9> <c#RRGGBB> <bg#RRGGBB>`

**为什么 iOS 这么便宜（24KB vs 安卓 80KB）**：

```
安卓：hook Compose 最深处 fz2.p(AnnotatedString)
      还要模仿 AnnotatedString.Builder / SpanStyle / Color 一整套私有 API

iOS：  hook -[UILabel setAttributedText:] 就够了
      因为苹果早把富文本标准化成 NSAttributedString 了
```

> **方法论**：找「所有渲染路径的**收口**」比找「每个入口」便宜得多。

**判定优先级（顺序不能反）**：
```
① ⟦FDM:xxx⟧      模板模式（有冒号）
② ⟦FDM⟧…⟦/FDM⟧  匿名包裹 → 渲染（不是删除！）
③ 裸标签模式
④ 残留标记 → 交给 FDMStripMarks 删除
```
② 必须在 ④ 之前，否则 AI 写的包裹标记会被当系统提示词删掉。

**两个技术点**：
- 字体派生用 `fontDescriptorWithSymbolicTraits:`，不用 `boldSystemFontOfSize:`
  （后者会丢字体族 ⇒ 一个字 PingFang 一个字 System 的割裂感）
- base attributes 从「标记所在位置」取，不从第 0 位取

## 三、❌ 没做成的（诚实版）

### 3.1 P3 · 账号名 ⚠️ 半成

**做成的部分**：
- MMKV 二进制格式**完全解开**（两种变体 + CRC 结构，文档 20）
- 离线改写工具 `tools/mmkv_patch.py` 可用
- 存储层**确实改成功**：从设备 pull 下来的文件里 `mobile = '尼得亚伯'`
- Hook 也命中 6 次：`[mmkv] ★ currentUser 改名 → 「尼得亚伯」`

**没成的部分**：**界面还是手机号**。

**根因推测**（按可能性排序）：
1. 宿主启动时把 `currentUser` 读进内存，之后一直用内存副本 ← 最可能
2. 有独立的 account 缓存（另一处存储 / 服务端拉取）
3. 抽屉的账号名另有数据源

**下一个方向**：不再碰存储，改 hook **渲染账号名的那个 UILabel/Text**（跟安卓一样走 UI 层）。

### 3.2 P3 · 头像 ❌

`currentUser` 结构里**既没有 nickname 也没有 avatar**（跟安卓完全一致）。
头像只能走 UI 层（换 UIImageView 的图）。

### 3.3 气泡透明（`bg_clear_all`）⚠️ 已关闭

**根因**：它是「无差别清所有容器底色」，在聊天页是美学，在白字列表页是灾难：

| 页面 | 清掉底色后 |
|---|---|
| 聊天页 | 气泡融进背景（好看） |
| 会话抽屉 / 设置页 | 白字压在亮照片上，亮处整片「看不见」 |

**尝试过的修法（都失败了）**：
- 加聊天页白名单 → 但 `bt_scrollLayout` / `bt_cellLayout` 是**全局** hook，还在清
- 给 hook 加 view 级判定 → 抽屉正常了，但气泡透明也丢了
- 给面板加实底 → 设置页变成完全不透明，还引入「断连」

**结论**：当前选择「关掉 clear_all，保证列表可读」。气泡透明的正确解法是
**按类名精确清理**（只碰 MessageCell / FragmentView / BubbleView），
绝不整棵树遍历 —— 留待下次。

## 四、💥 今天搞坏的（已修复）

| 事故 | 原因 | 后果 |
|---|---|---|
| **登录态丢失** | 删了 `mmkv.default.crc`，宿主判定文件损坏 | 宿主重建 MMKV，`settingsToken` 丢失 ⇒ 主人重新登录 |
| App 起不来（多次） | iPhone 7P 只有 2GB，内存不足 | 无崩溃日志 + 进程不出现 |
| 抽屉列表「消失」 | `bg_clear_all` 清掉了白字列表的容器底 | 白字被亮背景吃掉 |
| 🦖 菜单不见 | 同上 | 同上 |

> **教训**：`mmkv.default.crc` 绝对不能删。
> 删了不是「让它重算」，是「告诉它文件坏了」——它会直接丢数据。

## 九、给下次的三句话

> **1. 先找「收口」，再动手。**
> 安卓为了富文本 hook Compose 最深处，模仿一整套私有 API，花了 80KB。
> iOS 只要一个 `-setAttributedText:` —— 同一个功能代价差 4 倍。
>
> **2. 看不见的东西，要用看得见的方式验证。**
> 文档 14 判「抹除全灭」，其实只是测错了模式。
> 换成可观测的模式，同一套代码立刻生效。
>
> **3. 改别人的存储，先问「它有几层缓存」。**
> MMKV 只是第一层，宿主读过会放进内存，甚至可能还有服务端副本。
> 改磁盘 ≠ 改界面。而且 `.crc` 不能删 —— 删了等于告诉它「文件坏了」。
