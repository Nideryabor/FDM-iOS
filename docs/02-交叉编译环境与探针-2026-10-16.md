# 02 · 交叉编译环境 & FDMProbe 探针

> 2026-10-16 · 尼得亚伯 🐲
> 结论先行：**小窝（Ubuntu 24.04 aarch64）可以直接交叉编译出 iOS arm64 的 dylib，全流程已实测跑通。**

---

## 一、为什么能通（原理）

Theos 在 Linux 上交叉编译 iOS，缺的从来不是 clang（clang 天生多目标），而是这三件事：

| 缺什么 | 症状 | 我们的解法 |
|---|---|---|
| **Mach-O 链接器** | 找不到 `ld` / 用了 GNU ld | `/opt/theos/toolchain/linux/iphone/bin/ld` → `ld64.lld`（LLVM 自带） |
| **`-platform_version`** | `ld64.lld: error: must specify -platform_version` | 包装 clang 加 `-mlinker-version=711`（clang 据此改发新式 flag） |
| **代码签名（ldid）** | `Signing …: ldid: command not found` | 链接时加 `-Wl,-adhoc_codesign`，由 ld64.lld 直接产出 ad-hoc 签名；`ldid` 放占位脚本 |

### 关键卡点复盘（都是实打实踩出来的）

1. **`bin/update-theos` 拒绝以 root 运行** → 改为手动 `git submodule update --init --recursive`，跳过脚本。
2. **`raw.githubusercontent.com` 在国内四个 IP 全被 RST** → Theos 走的是 `git clone`（`github.com`），所以不影响；只有需要 raw 的地方才要另想办法。
3. **`github.com` IP 漂移** → `20.205.243.166` 可用；写进 `/etc/hosts`。
4. **apt 源要换 USTC**，`ports.ubuntu.com` 通但慢到怀疑人生（换完 11 MB/s）。
5. **`-mlinker-version` 必须给**，否则 clang 发老式 `-iphoneos_version_min`，ld64.lld 不认。
6. **clang 包装必须用 `exec -a` 保住 argv[0] 的目录** —— 否则 clang 的 `InstalledDir` 变成 `/usr/bin`，就去找 GNU ld 了（报 `unrecognised emulation mode: llvm`）。

## 三、探针干了什么（FDMProbe.m）

设计原则：**纯 ObjC runtime 打桩（`method_setImplementation` + 调原 IMP）**，
**不依赖 logos / substrate / ellekit** —— 任何注入器都能跑，也不会因为注入框架差异翻车。

| 组 | 内容 |
|---|---|
| ① **MMKV** | `+mmkvWithID:` / `+defaultMMKV` 抓实例；`setObject/setString/setData/setBool/setInt64/setDouble/setFloat:forKey:` 抓写；`objectForKey/stringForKey/dataForKey/boolForKey/int64ForKey/doubleForKey/containsKey:` 抓读；`allKeys` 全量导出；`removeValuesForKeys:` 抓删 |
| ② **NSUserDefaults** | `setObject/setBool/setInteger:forKey:`、`objectForKey:`、`initWithSuiteName:` |
| ③ **类普查** | 枚举所有类，命中 `Setting/MMKV/KVStorage/RemoteSetting/Poller/Prompt/Persist/ABValue` 等关键词的：打父类 + own 实例方法 + own 类方法 + **ivar 名**（Swift 反射属性名就在 ivar 里） |
| ④ **镜像普查** | 列出含 DeepSeek/MMKV/WCDB/SmCaptcha/TRTC/Rangers 的已加载 image |
| ⑤ **30s 复查** | 用常见 ID 试探 `mmkvWithID:`，报告每个实例的键数 |

安全性：全程 `@try/@catch`；日志 > 8MB 自动停止写文件（只留 NSLog）。

日志落点：**App 沙盒 `Documents/fdm-probe.log`** + `NSLog`。

## 四、怎么用

### 1) 编译

```bash
source /workspace/ios-port/env.sh
cd /workspace/ios-port/src/FDMProbe && make clean && make
cp .theos/obj/debug/arm64/FDMProbe.dylib /workspace/ios-port/out/
```

### 2) 注入（TrollFools）

1. 把 `out/FDMProbe.dylib` 弄到 iPhone（微信/QQ/AirDrop/Filza 均可）
2. 打开 **TrollFools** → 选 **DeepSeek Chat** → 注入 → 选这个 dylib
3. 启动 DeepSeek

### 3) 取日志（两条路，任选）

- **Filza**：应用容器 → `Documents/fdm-probe.log`
  （路径提示：`/var/mobile/Containers/Data/Application/<UUID>/Documents/fdm-probe.log`）
- **os_log**：`Console.app` 或设备上 `log stream --predicate 'process == "DeepSeek Chat"'`

### 4) 卸载

TrollFools 里取消注入即可（或重装 App）。

## 五、探针要回答的问题（静态分析定不下来的）

| # | 问题 | 看日志里哪一行 |
|---|---|---|
| 1 | MMKV 实例 ID 是什么 | `★ MMKV 实例创建 mmkvWithID: X` |
| 2 | 设置键有没有前缀 | `★ MMKV 写[…] …` 里的 key 形态 |
| 3 | 设置走不走 MMKV | 有没有对应的 `★ MMKV 写`；若只有 NSUserDefaults 行 ⇒ 走 defaults |
| 4 | 本地覆盖层在哪 | `CLASS RemoteSettingsManager` / `CLASS APPKVStorage` 的 ivar 与方法表 |
| 5 | 服务端下发落地在哪 | `MMKV allKeys[…]` 全量键表 |
