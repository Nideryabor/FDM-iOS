## 为什么能这么改（先确认过的安全边界）

`FDMGroup.parent` 和 `order` **只影响 `childGroupsOf:` 的取数与排序**：

```objc
// FDMConfig.m —— enabledFor 只看自己的 enabled，不走上层链
- (BOOL)enabledFor:(NSString *)gid {
    id v = [self dictFor:gid][@"enabled"];
    return v ? [v boolValue] : YES;
}
```

所以挪 parent **不会**改：
- 每个页面的 `gid`（⇒ `fdm-*.json` 文件名不变）
- 任何配置键名、默认值、读写路径
- `enabledFor:` 的判定结果

⇒ 挪页 = 纯显示层的搬家，随时可以挪回来。

## ★ 顺手造的工具：`ui_auto_shot`（不用点屏幕也能截图）

### 为什么非要造

这一轮设备上：MCP `8090` 全关、没有 frida（`27042` 也没开）、
`/var/jb/usr/bin` 里 `snaputil` 只是 APFS 快照工具、**没有任何命令行截屏**。
⇒ 改完 UI 树，尼尼在电脑这头**完全看不见结果**，只能靠日志猜。
（第一版 `[tree]` 日志就是为此加的：注册完把运行时树打出来。）

### 它怎么工作

设置页得在 App **自己进程内**打开，才能在进程内 `drawViewHierarchy`。
所以让模块自己来。开关在「调试 → 📸 自动截图」（默认关）：

```json
// Documents/fdm-debug.json —— 这就是那个开关存的地方，手写也认
{ "ui_auto_shot": true, "ui_auto_shot_pages": "misc,chat,beauty" }
```

启动后自动：

```
18s  弹设置页（formSheet）→ 1.2s 后拍  fdm-ui-01-首页.png
21s  进 misc   → 0.8s 后拍             fdm-ui-02-misc.png
24s  进 chat   → 0.8s 后拍             fdm-ui-03-chat.png
…    每页 3s 一个
最后 自己 dismiss，不挡人
```

产物在 `Documents/fdm-ui-<序号>-<gid>.png`（2x 分辨率，~200-350KB）。

**过程中踩的坑（值得记）**：第一版用 `static __weak UINavigationController *`，
结果 `[autoshot] 没有 nav，跳过 misc` —— ARC 下 present 完成前没人强引用它，
赋值那行一过就被释放成 nil。**改成强持有、`End()` 里置 nil** 立刻正常。

**用法**（以后任何 UI 改动都建议这么验）：

点「调试 → 📸 自动截图」→ 填页面 id → **重启 App** → 等 ~35s → 拉图 → 点「🗑 清空截图」。

```bash
bash tools/iphone.sh restart
sleep 40
scp -P 2222 mobile@192.168.1.8:$APP_DOCS/fdm-ui-*.png ./tmp/
```

> ⚠️ 开关默认**关**，且**拍完会自己关回去**，不会次次弹。
> 设备上现在是 `{"ui_auto_shot": false, "ui_auto_shot_pages": ""}`，图也已清空。

## ★★ 隐私加固（主人指示：「做成开关，默认关，不然有隐私泄露嫌疑」）

`ui_auto_shot` 第一版只是**读 JSON 的隐藏标志**，等于「谁都能偷偷打开你也不知道」。
（代码里从没自动打开过，但这对用户是**不可验证**的承诺 —— 不可验证就等于没有。）
所以改成看得见的开关，上了六道闸：

### ① 变成 UI 开关，默认关

```
🔧 调试
  ├ 📜 查看日志
  ├ 📂 Documents 目录
  ├ 🗑 清空日志
  ├ 网络 Hook                [开]
  ├ 同时打 NSLog              [关]
  ├ 记录响应正文              [关]
  ├ X 光机（渲染层勘察）       [关]
  ├ 📸 自动截图（改 UI 时用）  [关] ← 默认关，说明里直接写清隐私风险
  ├ 要拍的页面 id            （文本框）
  ├ 🗑 清空截图                ← 一键删掉所有 fdm-ui-*.png
  └ 日志级别
```

字段：`P_DEBUG` / `ui_auto_shot`（Bool，默认 `NO`）+ `ui_auto_shot_pages`（String）。
触发点从「裸读 JSON」改成 `[[FDMConfig shared] boolFor:P_DEBUG key:@"ui_auto_shot"]`
⇒ **UI 写的值和触发读的值是同一个**（手写 JSON 也照样兼容，因为同一份 `fdm-debug.json`）。

### ② 只跑一轮：拍完立刻把开关关回去

```objc
if (shot) {
    [cfg setValueQuietly:@NO for:P_DEBUG key:@"ui_auto_shot"];   // ← 先关，再干活
    ...排程...
}
```

**先关再干活**是刻意的：中间哪怕崩了，也不会「下次启动再弹一次」。

### ③ 每轮先清上一轮的旧图

不然图会越攒越多，而每一张都可能含聊天内容。

### ④ 新增「清空截图」按钮

拉走图之后点一下，`Documents/fdm-ui-*.png` 全删，日志记删了几张、释放多少 KB。

### ⑤ 顺手修的：不把「自动关回」算成「用户改过」

`setValue:` 会把键塞进 `__mod`，于是 UI 上挂个 ⭐、首页显示「已改 1 项」——
可用户根本什么都没改。新增 `FDMConfig -setValueQuietly:for:key:`：
写值 + 从 `mods` 里摘掉这个键。截图对照确认 ⭐ 已消失。

### ⑥ 顺手修的：nav 时序

`FDMUIAutoShotBegin` 原来**先**把 nav 存进全局、**后**判断 `presentedViewController`。
一旦当时有别的模态 ⇒ nav 存进了全局却永远不会 present，后面 `Push` 往一个
不在屏幕上的 nav 里塞 VC，`rc=0` 看起来成功，其实拍的是宿主界面。
现在改成**先判空再持有**，并且日志明确写「本轮跳过」。

### 真机验证（三轮）

| 轮次 | 干了什么 | 结果 |
|---|---|---|
| 1 | 手写 `{"ui_auto_shot": true, "ui_auto_shot_pages": "debug,misc"}` + 重启 | ✅ 拍首页 + debug + misc 三张；`__mod` 里有 `ui_auto_shot`（⭐ 出现） |
| 2 | 装 `setValueQuietly` 后再拨一次 | ✅ 拍两张；`__mod` **不含** `ui_auto_shot`，截图里 ⭐ 消失 |
| 3 | 什么都不改，直接重启 | ✅ **一条 `[autoshot]` 都没新增**（45 → 45），开关停在 `false`，图没新增 |

验完已删掉设备上那两张图，`fdm-debug.json` 恢复成
`{"ui_auto_shot": false, "ui_auto_shot_pages": ""}`。

## 安全自查（主人问「你怎么知道我 mobile 密码」之后做的）

**结论：我没见过明文。** 全过程走的是 `tools/_env.sh` 把 `IPHONE_PW` 导入成 `$PW`，
再交给 `sshpass` —— 值只在进程环境里，没进过我的上下文。

证据：

| 检查 | 结果 |
|---|---|
| 我这一轮自己写的 `/tmp/pull.sh` | 只 `source .env` + 用 `$IPHONE_PW`，**没有字面量** |
| `tools/env.py` 打印 | 只打长度（`***（11 字符）`） |
| `diff .env .env.bak-1024-ip` | 只有 `IPHONE_HOST` / `IOS_MCP_HOST` 两行差异，没碰口令行 |
| `.env` 与 3 个 `.env.bak-*` | 全是 `-rw-------`，且被 `.gitignore`（`/ios-port/.env`）挡住 |

### ⚠️ 但顺手翻出两个真隐患，建议尽快处理

**1. 口令被拼进远端命令行（高危 · 4 个脚本都有）**

```bash
# tools/dep.sh:27（deploy.sh / elikit.sh / dep-troll.sh 同样写法）
"cat > /tmp/_s.sh && echo '$PW' | sudo -S -p '' sh /tmp/_s.sh"
```

`$PW` 在**本地**被展开进 SSH 的远端命令串 ⇒ 执行的那一两秒里，
设备上 `ps aux | grep sudo` 能看到明文口令（任何能跑 `ps` 的进程都能看到）。
**改法**（口令只走 stdin，不进 argv）：

```bash
printf '%s\n' "$PW" | sshpass -p "$PW" ssh $SSH_OPTS "$USER@$HOST" \
    "sudo -S -p '' sh -s" <<'EOS'
cp /path/new.dylib /var/jb/usr/lib/TweakInject/FDM.dylib
ldid -S /var/jb/usr/lib/TweakInject/FDM.dylib
EOS
```

**2. 备份目录里躺着一条旧的硬编码口令**

`backups/pre-env-fix/iphone.sh:19` —— `PW="${IPHONE_PW:-<明文>}"`。
这是「还没搬家到 .env」时代留下的，现在 `.env` 已经接管，这个 fallback 纯属负债
（还会诱导以后的人继续用弱口令兜底）。建议直接删掉那一行，或整个
`backups/pre-env-fix/` 打包压掉。

> 两处都**没动** —— 等主人拍板再改，因为都要碰部署链路。
