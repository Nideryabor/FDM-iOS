## 二、三种卡片、三套手势

| 卡片 | 抽屉 → 容器 | 说明 |
|---|---|---|
| **内置三张**（回复建议/音乐/富文本） | **搬** | 抽屉里那份没了；右边 `▸` 跳对应设置页 |
| **文本源卡**（系统提示词内容） | **复制** | 抽屉里留一份，容器里**追加新副本**，能无限拖 |
| **自定义副本** | **搬** | 可编辑标题/正文/「标题也进」；在抽屉里才有 🗑 |

> 为什么要区分「搬」和「复制」：
> 内置卡只有一份，它代表「要不要那段约定」，所以是开关语义（搬）。
> 源卡是**模板**，用户想加几张就几张，所以是复制语义。

## 三、★ 为什么内置卡的文案由**引擎**提供

安卓原注释（`SysPromptV2.kt:308`）写得很好，我原样保留：

> 内置三张卡只送类型名 —— 它们"自带的"那一大段文案由**宿主自己取**
> （`GmRichText.suggestSpec()` / `GmPromptVars.spec()` / `GmRichText.spec()`），
> 免得同一份文案在界面里再抄一份、两边各说一套。

iOS 上对应 `fdmpc_builtin_spec(type)`。

**好处**：改一处文案，界面和实际注入自动同步。
**风险**：iOS 和安卓的文案必须**手动保持同步**（两个代码库，没有共享源）。
所以我在文档里把三段原文抄下来了，改的时候对着改。

## 四、★ 归一化：坏存档不能把页面卡死

这是整个存档最容易出事的地方。安卓 3.62.2 修过一次「三个内置卡片被当夜宵吃了」。

`pc_normalize()` 五条规则：

| # | 规则 | 为什么 |
|---|---|---|
| ① | 列表里有、卡片表没有的 key → 补一张卡 | 存档被手动改过 / 上一版删了卡但列表没清 |
| ② | 类型不认识的卡 → 丢掉 | 别让未知类型把 UI 撑坏 |
| ③ | **内置三张 + 源卡必须存在，缺了补回抽屉** | 它们删不掉，丢了必须长回来 |
| ④ | 同 key 不许同时在两个列表 | 会出现「搬进去但抽屉还有」的幽灵 |
| ⑤ | 数量超上限 → 截断 | 防呆（上限 200） |

另外单独一条：**源卡不该出现在容器里**（它在容器里会让"复制"语义变成"搬"，逻辑就乱了）。

## 五、这一轮抓到的 bug（都是自己写的）

### 5.1 JSON 输出多了一对引号

```objc
// ❌ 错
o += sprintf(o, "%s\"", i ? ",\"" : "\"");
// 第一个元素：%s 是 `"`，再拼 `\"` ⇒ 输出 `""music`
//            ↑↑ 两个引号，JSON 全坏

// ✅ 对
o += sprintf(o, "%s", i ? ",\"" : "\"");
```

输出变成 `""music",""richtext"` ⇒ `from_json` 读到空 key ⇒ 全丢 ⇒ rc=-1。

**这个 bug 特别隐蔽**：`from_json` 的归一化把坏数据救回来了，看起来"能用"，
但**用户拖进去的卡片会静默消失**（因为存档是坏的）。

### 5.2 测试自己的锅（两次）

| 断言 | 错在哪 |
|---|---|
| `compose 应等于内置文案` | `compose` 会对每段 `trim`（**和安卓 `seg.trim()` 一致**），末尾 `\n` 被去掉 ⇒ 不能直接 `strcmp` 原文 |
| `compose 应跟着重排` | 用完整文案 `strstr` 找不到（同样因为 trim）⇒ 必须用**特征串** `【音乐变量】` 定位 |

> 教训：**测试断言写错比代码写错更难查** —— 你会以为是实现有问题。

### 5.3 `@(char*)` 不能包

```objc
NSString *t = @(FDMPC_T_SUGGEST);        // ❌ char* 不能这么包
NSString *t = @FDMPC_T_SUGGEST;          // ✅
NSString *t = [NSString stringWithUTF8String:FDMPC_T_SUGGEST];  // ✅ 最稳
```

还有 `card->text ?: @""` —— 三元两边类型不一致（`char*` vs `NSString*`）。

### 5.4 `itemsForBeginningSession` 少了 "Drag"

协议方法名是 `collectionView:itemsForBeginningDragSession:atIndexPath:`。
写错就变成"未实现协议方法" → `-Werror` 直接编译失败。

## 九、给下次的三句话

> **1. `sprintf("%s\"", "\"")` 会输出两个引号。**
> 分隔符要放进 `%s` 里，格式串**别再加 `\"`**。
> 这种 bug 不会崩，只会让存档静默坏掉 —— 而且归一化还会把坏数据"救"回来，
> 让你以为一切正常，直到用户发现自己拖的卡片消失了。

> **2. 测试断言写错比代码写错更难查。**
> 这次两次失败都是断言自己的锅（compose 会 trim / 用完整文案 strstr 找不到）。
> 判「顺序」要用**短特征串**定位，别用完整文案。

> **3. 归一化是存档的最后一道防线。**
> 「内置卡丢了要长回来」「孤儿 key 要补卡」「未知类型要丢」——
> 这三条不做，用户改一次 json 就再也进不去这个页面了。
