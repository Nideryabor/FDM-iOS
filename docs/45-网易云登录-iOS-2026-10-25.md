## 一、为什么登录走 weapi，不是 eapi

| | eapi | weapi |
|---|---|---|
| URL | `interface.music.163.com/eapi/<uri>` | `music.163.com/weapi/<uri 去掉 /api/>` |
| body | `params=HEX(AES-ECB)` | `params=base64&encSecKey=RSA` |
| UA | iPhone/Android/PC 档位可切 | 固定 PC Chrome/Edg |
| 用在哪 | 搜索 / 播放地址 / 歌词 / 详情 | **登录系列** |

NeteaseCloudMusicApi 的 `util/request.js` 里就是这么分的 —— 登录系列属于 weapi 分支。
iOS 早就移植好了 `fdm_music_weapi()`（纯 C，与 Java 版逐字节对拍过），
只是**一直没人调用**。这次接上。

## 二、★ 核心坑：MUSIC_U 在 302 那一跳上

### 2.1 症状有多坑

```
界面：✅ 登录成功
实际：什么都没存上
下次：照样未登录，VIP 歌还是只放 30 秒
```

日志里也只是 `code=200` —— 看起来完美。

### 2.2 病根

网易云登录接口的典型响应链：

```
POST /weapi/w/login/cellphone
  ← 302 Found
      Set-Cookie: MUSIC_U=xxxxx; Path=/; Domain=.music.163.com; HttpOnly   ← ★ 在这！
      Location: https://music.163.com/...
  （自动跟随）
GET https://music.163.com/...
  ← 200 OK
      Set-Cookie: __csrf=...        ← 只有这个了
```

**NSURLSession 默认自动跟随重定向**，而 `completionHandler` 只拿到**最终响应**的头。
302 那一跳的 `Set-Cookie: MUSIC_U` 就这么没了。

### 2.3 解法（安卓 2026-10-06 已经踩过，iOS 这次照抄）

```objc
cfg.HTTPShouldSetCookies = NO;                       // 不自动存
cfg.HTTPCookieAcceptPolicy = NSHTTPCookieAcceptPolicyNever;   // 也不进 shared 池

// ★ 必须用 delegate 版 session，不然 willPerformHTTPRedirection 根本不触发
NSURLSession *session = [NSURLSession sessionWithConfiguration:cfg
                                                     delegate:poster
                                                delegateQueue:nil];
```

然后在 delegate 里**逐跳收 cookie**：

```objc
- (void)URLSession:(NSURLSession *)session
              task:(NSURLSessionTask *)task
willPerformHTTPRedirection:(NSHTTPURLResponse *)response
        newRequest:(NSURLRequest *)request
 completionHandler:(void (^)(NSURLRequest *))completionHandler {
    FDMHarvestCookies([response allHeaderFields], response.URL, self.jar);  // ★
    if (self.hops++ > 5) { completionHandler(nil); return; }                // 防死循环
    NSMutableURLRequest *nr = [request mutableCopy];
    [nr setValue:<weapi UA> forHTTPHeaderField:@"User-Agent"];              // 重定向会丢 UA
    completionHandler(nr);
}
```

### 2.4 收 cookie 别自己 split

```objc
// ❌ 错：allHeaderFields 会把多个 Set-Cookie 合并成一行逗号分隔，手拆必错
NSArray *parts = [headers[@"Set-Cookie"] componentsSeparatedByString:@","];

// ✅ 对：用 NSHTTPCookie 解析
NSArray<NSHTTPCookie *> *cks =
    [NSHTTPCookie cookiesWithResponseHeaderFields:headers forURL:url];
```

### 2.5 加一条防御：区分「登录失败」和「登录成功但没拿到凭证」

```objc
if (code == 200 && !mu.length) {
    // 这两件事的提示语完全不同，别混
    completion(NO, @"服务端说成功，但没拿到凭证（把日志发给尼尼）", jar);
}
```

不然用户只会看到"失败"，我们永远查不出是重定向没跟上。

## 三、三条登录路（参数照抄，别自己猜）

### ① 发短信验证码

```
POST /weapi/sms/captcha/sent
{
  "ctcode": "86",
  "secrete": "music_middleuser_pclogin",   ← ★ 写死的，别改
  "cellphone": "13800138000"
}
```

### ② 手机 + 验证码

```
POST /weapi/w/login/cellphone
{ "type":"1", "https":"true", "phone":"…", "countrycode":"86",
  "captcha":"1234", "remember":"true" }
```

### ③ 手机 + 密码

同一个 URL，把 `captcha` 换成 `password`，值是 **md5(明文)**。

```objc
NSString *md5 = [FDMMusicApi md5Hex:password];   // 内部走纯 C 的 fdm_md5_hex
```

### ④ 邮箱 + 密码

```
POST /weapi/w/login
{ "type":"0", "https":"true", "username":"a@b.com",
  "password":"<md5>", "rememberLogin":"true" }
```

⚠️ 注意 `type` 从 `"1"` 变成 `"0"`，字段名从 `phone` 变成 `username`，
`remember` 变成 `rememberLogin` —— 四个字段全不一样，别复制粘贴搞混。

### ⑤ 粘 cookie（不发请求）

用户从浏览器开发者工具里复制，可能是三种形态：

| 形态 | 例子 |
|---|---|
| 整条 Set-Cookie | `MUSIC_U=abc…; Path=/; Domain=.music.163.com; HttpOnly` |
| 只有一对 | `MUSIC_U=abc…` |
| 纯值 | `abc…`（≥20 字符，不含 `=` 和 `;`） |

三种都要能认。**判断顺序很重要**：
先按 `k=v` 解析，解析不到再判"纯值形态"（**长度 ≥ 20 且不含 `=`/`;`**）。

> 为什么要长度门槛：不然用户粘个 "abc" 也当凭证，然后一直登录失败查不出原因。

### ⑥ 查登录状态

```
POST /weapi/w/nuser/account/get   {}
```

判断**不能只看 code=200**：

```objc
id acct = r[@"account"];
BOOL ok = (code == 200 && acct && ![acct isKindOfClass:[NSNull class]]);
// ★ 凭证过期时也是 code=200，但 account 是 null
```

```json
  "nick": "周杰伦",
  "at": 1761340000
}
```

### ⚠️⚠️ 隐私红线（主人 2026-10-06 在安卓那边明确要求）

**明文存储**。必须做三件事：

1. **界面上写清楚**（`FDMFeatures.m` 的 musiclogin 页 note 里已经写了）
2. **登录成功后清空密码 / cookie 输入框** —— 因为 `FDMConfig` 会把所有字段
   明文写进 `fdm-music-login.json`，不清就等于把密码长期存盘
3. **iOS 额外做**：把目录标记 `NSURLIsExcludedFromBackupKey`
   （安卓没这个需求，但 iOS 的 Documents 会被 iTunes/iCloud 备份带走）

```objc
NSURL *u = [NSURL fileURLWithPath:sub];
[u setResourceValue:@YES forKey:NSURLIsExcludedFromBackupKey error:NULL];
```

> 这条是 iOS 独有的。安卓那边写的是 `/data/data/<宿主>/files/`，
> 别的 App 拿不到（除非 root）；iOS 的 Documents 反而更容易被备份导出。

## 五、安卓那边踩过、iOS 也踩了的一个坑

> 「`save()` 以前对**空凭证直接 return，连日志都不打** ⇒
>  症状是'登录提示成功、实际什么都没发生'，查起来像见鬼。」

所以 `FDMMusicLoginSave` 里：

```objc
if (!mu.length) {
    LoginSetOp(@"保存失败：凭证是空的");   // ★ 永远留一句话
    return NO;
}
```

并且 `FDMMusicLoginLastOp()` 把这句话暴露给界面 —— 用户和排查的人都能看到。

## 九、给下次的三句话

> **1. `Set-Cookie` 在 302 那一跳上，自动跟随重定向会把它吃掉。**
> 解法：`HTTPShouldSetCookies=NO` + `delegate` 版 session +
> `willPerformHTTPRedirection` 里逐跳收。
> **这不是网易云的怪癖，是所有"登录先跳转"的通用问题。**

> **2. 收 cookie 用 `NSHTTPCookie`，别自己 split。**
> `allHeaderFields` 会把多个 `Set-Cookie` 合并成一行逗号分隔，
> 而 cookie 值里本身可能就有逗号（`Expires=Wed, 21 Oct…`）。

> **3. 空凭证必须留一句话。**
> 安卓那边"提示成功、其实没发生"查了很久，就是因为 `save()` 静默 return。
> 现在 `FDMMusicLoginLastOp()` 永远有话说，界面能看到。
