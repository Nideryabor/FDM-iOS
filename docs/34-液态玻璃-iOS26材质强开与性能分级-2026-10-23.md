## 〇、一句话

之前文档 13 写「液态玻璃 🚫 跳过，因为 iOS 没有 RuntimeShader 对等物」。
这个判断**只对了一半** —— 真折射确实做不到，但**材质感的 80% 不靠折射**，
靠的是「模糊调参 + 边缘高光 + 厚度渐变」，这三样 iOS 15 全都有。
所以这一轮把它做了，并且做成了**可分级、可降级、可测帧时间**的东西。

---

## 一、先摆清楚：哪些能做，哪些做不到

| Liquid Glass 的构成 | iOS 15 能做吗 | 我们的做法 |
|---|---|---|
| 背景模糊（大半径、保细节） | 可以 | `_UICustomBlurEffect` 调 radius / saturation |
| 饱和度提升 | 可以 | `saturationDeltaFactor = 1.85` |
| **边缘高光**（specular） | 可以 | 45 度渐变 + 圆角描边 mask |
| **玻璃厚度**（上亮下暗） | 可以 | 内部透光渐变 |
| **透镜放大** | 可以 | effect `scale = 1.02`（真的在放大采样） |
| **屏幕空间折射（弯曲）** | 不行 | 拿不到宿主合成好的背景纹理 |
| 动态镜面反射（跟着陀螺仪） | 不行 | 同上 |
| 系统级材质（跨 App 一致） | 不行 | 我们只是宿主进程里的图层 |
| iOS 26 的 `UIGlassEffect` | 真的 iOS 26 才有 | 探测到就用，探测不到退回自合成 |

**结论：视觉上接近，机制上不是一回事。** 不要对用户说「这是 iOS 26 的液态玻璃」。

## 二、怎么「强开」

### 2.1 只升级宿主已有的玻璃，不给所有控件硬加

勘察结果：宿主自己就在用 `UIVisualEffectView` / `UIBlurEffect`
（导航栏、顶部 `DeepSeek_Chat.VariableBlurView` 那个盖 214px 的毛玻璃…）。

所以策略是**原地升级**：

```
宿主： UIVisualEffectView + UIBlurEffect(style)
                    ↓ 我们只改 effect 参数 + 叠两层装饰
FDM：  UIVisualEffectView + _UICustomBlurEffect(radius 22, sat 1.85)
                          + 边缘高光层
                          + 内部透光层
```

为什么不能「遍地新建」：A10 + 2GB 上，给几百个 UIButton 各塞一层模糊 = 直接卡死。
而宿主原有的模糊**成本已经付过了**，我们只是把它改造成玻璃。

### 2.2 `_UICustomBlurEffect` 是私有类 —— 怎么保证不炸

```objc
Class c = NSClassFromString(@"_UICustomBlurEffect");   // 找不到 → 放弃
id e = [[c alloc] init];
if (![e isKindOfClass:[UIVisualEffect class]]) → 放弃  // 不是 effect 子类 → 放弃
[e setValue:@(22.0) forKey:@"blurRadius"];             // 设不进 → @catch 放弃
[e setValue:@(1.85) forKey:@"saturationDeltaFactor"];
```

三次探测，任一步失败就**只做高光不做模糊**（T1），
而且这个「能不能用」的结论**进程内只探一次**，不反复试。

### 2.3 iOS 26 走原生：只按类名探，不猜 API

```objc
if (NSClassFromString(@"UIGlassEffect")) { → T4 直接用系统 }
```

**不写 `@available(iOS 26, *)` + 硬编码方法名** —— 因为：

- 我们的 SDK 是 15.6，根本看不到 iOS 26 的头文件
- 硬写名字，Apple 一改名就是编译期看不到、运行期崩
- 按类名探 + `isKindOfClass:` 验证，改名就自动退回自合成，**不会崩**

## 三、性能分级：三层输入，不是拍脑袋

用户特别要求「加个性能分级」。这一块做了**三层**，缺一层都不够。

### 3.1 第一层：硬件评分（0..9）

| 维度 | 加分 | 例 |
|---|---|---|
| 核心数 | 大于等于 8 加 3 / 大于等于 6 加 2 / 大于等于 4 加 1 | A10=4核加1，A13=6核加2 |
| 内存 | 大于等于 6G 加 3 / 大于等于 4G 加 2 / 大于等于 3G 加 1 | 7P=2G加0，12=4G加2 |
| GPU family | 大于等于 Apple7 加 3 / 大于等于 Apple5 加 2 / 大于等于 Apple3 加 1 | A10=Apple3加1，A14=Apple7加3 |

实测落档（39 组断言里的前 10 条）：

| 机型 | 核心/内存/GPU | 分 | 落档 |
|---|---|---|---|
| iPhone 7P (A10) | 4 / 2G / Apple3 | 2 | **T2** |
| iPhone 8 (A11) | 6 / 2G / Apple4 | 3 | T2 |
| iPhone X (A11) | 6 / 3G / Apple4 | 4 | T2 |
| iPhone XR (A12) | 6 / 3G / Apple5 | 5 | T2 |
| iPhone 11 (A13) | 6 / 4G / Apple6 | 6 | **T3** |
| iPhone 12 (A14) | 6 / 4G / Apple7 | 7 | T3 |
| iPad Pro (M1) | 8 / 8G / Apple9 | 9 | T3 |

> **T2 是默认档，不是「高性能档」** —— 因为宿主本来就在模糊，
> 我们只是把参数换成玻璃该有的样子，增量成本约为 0。真正需要性能的是 T3。

### 3.2 第二层：运行时状态（每条都可能降一档）

| 输入 | 效果 | 理由 |
|---|---|---|
| `UIAccessibilityIsReduceTransparencyEnabled()` | **降到 T0** | 这是无障碍的**义务**，不是优化（系统自己的模糊也会因此变不透明） |
| `isLowPowerModeEnabled` | 减 1 档 | 省电模式下别抢 GPU |
| 同屏玻璃多于 16 块 | 减 1 档 | 填充率保护（weak 表实时统计） |
| 滚动中 / 键盘弹出 | T3 降到 T2 | 只砍重活；T2 是宿主原有成本，不动 |
| `UIAccessibilityIsReduceMotionEnabled()` | 只关动效 | 材质不变，只去掉响应动画 |

### 3.3 第三层：**实测帧时间**（最可靠的一层）

硬件型号只能「猜」。真正的判据是**这台机器跑这个界面到底掉不掉帧**。

```
CADisplayLink（60fps，common modes）
  → 每 40 帧（约 0.67s）算一次平均帧耗时
  → 超过预算（T2/T3 = 20ms，T1 = 40ms）
  → penalty 加 1 → 降一档 → 本会话锁死，不再升
```

为什么「锁死不再升」：否则会出现
「卡 → 降档 → 不卡了 → 升档 → 又卡」的**闪烁循环**，比一直低档更难受。

`fdmgp_note_frame_ms()` 是纯 C 的，所以这条路径也能在小窝里测（断言 27 到 30）。

## 四、装饰层怎么画（三个 layer，成本极低）

```
zPosition 101  ─ 折射内缘线（只 T3）：2pt 白线，alpha 很低
zPosition 100  ─ 边缘高光：CAGradientLayer(45 度) + 圆角描边 mask
zPosition  99  ─ 内部透光：CAGradientLayer(垂直) 上白 0.10 → 透明 → 下黑 0.045
───────────────────────────────────────────────────────
                UIVisualEffectView 自己的模糊
```

三个关键细节：

1. **描边是居中的**：`CAShapeLayer.lineWidth = 1` 会向内向外各溢 0.5pt，
   所以高光线的宽度要取 `2 x 期望宽度`，视觉上正好一半可见。
2. **深色模式要打折**：`hA *= 0.55`，否则白色高光在深色背景上刺眼。
3. **每帧必须早退**：`layoutSubviews` 每帧都调，
   不做守卫就会每帧 new 一个 `CAGradientLayer` + `CAShapeLayer`。
   守卫判据：`bounds + 圆角 + 档位 + 高光强度 + 折射标志` 拼成字符串比较，
   一样就直接 return。

## 六、这一轮踩到的五个坑

| 坑 | 表现 | 解法 |
|---|---|---|
| `CALayer` 没有 `tag` 属性 | 编译期 5 处报错 | 用 `layer.name` 存字符串（顺带日志可读） |
| `layoutSubviews` 里每帧 new layer | 潜在掉帧 | 拼签名比较，没变就 return |
| 装饰层用 `addSubview` 会污染 contentView | 宿主内容被盖 | 全程走 `vev.layer addSublayer:`，不碰视图树 |
| `setEffect:` 会被我们自己触发 | 无限递归 | `__thread` 标记防重入 |
| T1 把 effect 置空会更难看 | 露出未模糊背景 | T1 保留宿主原 effect，只是**不加**模糊增强 |


**开关**（`Documents/fdm-debug.json`，合并别覆盖）：

```json
{
  "glass_on": true,
  "glass_tier": -1
}
```

| 键 | 值 | 说明 |
|---|---|---|
| `glass_on` | `false` | 完全不装（一条 hook 都不下） |
| `glass_tier` | `-1` | 自动（默认，按上面三层判） |
| | `0` | 强制关 |
| | `1` | 高光（无模糊增强，最省） |
| | `2` | 模糊 + 高光（主力档） |
| | `3` | 加折射感（A12/4G 以上才有意义） |
| | `4` | 原生（仅 iOS 26+ 有效，否则自动退回） |

> 强制档**仍受硬件上限约束**：A8 上写 3 会被钳到 2。
> 只有 `reduce_transparency` 是无条件的（那是义务）。

## 八、下次开工

1. **真机部署，先看 `_UICustomBlurEffect 可用` 那行** —— 决定后面是「调参」还是「换方案」
2. 看宿主哪些控件真的被接上了（`[glass] 标记 <类名>`，需要日志级别 D）
3. 如果 T2 看起来「糊成一团」：`blur_radius` 从 22 往 16 调（7P 上 22 可能偏大）
4. 如果高光看不见：先把 `highlight_alpha` 临时改成 1.0 并染成红色
   —— 文档 30 的铁律「没看见不等于没画出来」
5. 想更接近 iOS 26：唯一真正的下一步是**给这几个 layer 换成 Metal shader**
   （`CAMetalLayer` + 屏幕空间扭曲），但那要改渲染管线，风险和收益不匹配，暂时不做

### 明确没做

| 项 | 为什么 |
|---|---|
| 真屏幕空间折射 | iOS 15 UIKit 层拿不到背景纹理 |
| 陀螺仪驱动的镜面反射 | 需要 `CMMotionManager` 常驻，耗电，7P 上也不明显 |
| 给所有按钮/卡片硬套玻璃 | A10 上必卡（这是「原地升级」策略的原因） |
| 设置页里的档位选择 UI | 没真机不敢加 UI，先用 `fdm-debug.json` |

## 九、给下次的三句话

> **1. 「做不到」要先拆成零件再判断。**
> 「液态玻璃做不了」这句话下面藏着 8 个零件，其中 6 个能做。
> 一刀切否决 = 把一个功能整个扔掉。

> **2. 性能分级必须有「实测」那一层。**
> 硬件型号能猜、场景能算，但只有帧时间能告诉你**这台机器跑这个界面**到底行不行。
> 而且降级之后要**锁死**，否则会在两档之间来回闪。

> **3. 私有 API 要三重探测，不要信版本号。**
> 类在不在 → 类型对不对 → 参数设不设得进。
> 任一步失败就退到「只做高光」，比「假设它一定在」安全一个数量级。
