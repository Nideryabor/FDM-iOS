# 40 · 宿主 2.7.1：类名剥离 + 助手头像被移除

> 2026-10-24 · 尼得亚伯 🐲
> 承接 docs/37（气泡翻盘）、docs/39（助手图片）
> 触发：主人装回 App 时发现版本变成了 2.7.1

---

## 〇、三句话总结

1. **2.7.1 把 Swift 类名字符串全部从二进制里剥离了**（`_TtC13DeepSeek_Chat` 534 → 0）
   —— 但**运行时类名完全没变**，所有功能自动兼容。
2. **iOS 宿主的助手头像功能被彻底移除了**（不是灰度关掉，是代码删了）。
3. 旧版 1.2.6 有 `avatar` 字段 ⇒ 这个功能**曾经存在，后来被删**。

---

## 一、2.7.1 做了什么

### 1.1 静态对比（二进制）

```
                         2.6.2      2.7.1
_TtC13DeepSeek_Chat       534    →     0
DeepSeek_Chat.            273    →     0
.swift                    457    →     0
DeepSeek_Chat/            230    →     0
```

二进制大小：23,852,672 → **25,368,432**（大了 1.5MB，说明加了新功能）

⇒ 官方做了 **Swift metadata stripping**：把类名、源文件路径、
`__swift5_reflstr` 里的反射字符串都抹掉了。

**为什么这么做？** 大概率是防逆向 / 减小体积。

### 1.2 但运行时完全没变 ★★★

这是最重要的发现。尼尼写了个「零类名依赖」的测绘器（`FDMMap271.m`），
跑起来一看：

```
_TtCC13DeepSeek_Chat13InputAreaView13TextInputView
_TtCC13DeepSeek_Chat13InputAreaView15PromptInputView
_TtCC13DeepSeek_Chat13InputAreaView16VoiceInputButton
DeepSeek_Chat.AgentMessageCell
```

**类名一个没变。** 剥离只发生在**文件的字符串表**里，
`__objc_classlist`（12840 字节）和 `__objc_const` 都还在，
运行时 `class_getName()` 照样返回完整名字。

### 1.3 结论：不需要重新适配

真机日志（2.7.1 上跑 v62 模块）：

```
[bubble] 对方：底色 (0,0 366x499) r=18.0 / 容器 366x499      ← 气泡正常
[assistant] 头像 22x22@1,12/414x567 容器 414x567 空隙可用 24  ← 头像正常
```

**气泡和助手图片两个功能，在 2.7.1 上零改动直接可用。**

> ⚠️ 但**静态分析工具要改**：
> 以前用 `strings` 找类名的办法（`mstr.py --grep AgentMessageCell`）在 2.7.1 上会返回 0 命中。
> 不是「类没了」，是「名字不在字符串表里了」。
> 判断类是否存在，要么跑起来用 `objc_getClass()`，要么解析 `__objc_classlist`。

## 二、助手头像：iOS 上被彻底移除

### 2.1 完整证据链

| 证据 | 2.6.2 | 2.7.1 | 旧版 1.2.6 |
|---|---|---|---|
| 类 `AgentMessageView.AvatarView` | ✅ 有 | ✅ 有（运行时） | ✅ 有 |
| 类被代码引用（ADRP+ADD） | **0 处** | 0 处 | **0 处** |
| `AgentMessageView` 有 avatar ivar | ❌ | ❌ | ✅ **有** |
| 灰度键 `hide_assistant_avatar` | ❌ 搜不到 | ❌ 搜不到 | ❌ 搜不到 |

### 2.2 旧版 vs 新版的字段对比（决定性）

**旧版 1.2.6** · `AgentMessageView` 的字段顺序：

**新版 2.6.2/2.7.1** · 运行时 `class_copyIvarList` 实测：

```

$__lazy_storage_$_onToolOpenTapped
```

**⇒ avatar 没了。** 同时 `topTipViews` / `bottomTipViews` / `bubble` /
`thinkingView` / `searchView` / `currentMarkup` 也全没了 —— 说明 2.x 重构过这个视图。

### 2.3 自动化验证

扫全二进制的 `$__lazy_storage_$`：

| 版本 | 总数 | 「agent message 区含 avatar」 |
|---|---|---|
| 2.6.2 | 429 处 | **0** |
| 1.2.6 | 213 处 | **1**（fileoff 0xc93a51）|

### 2.4 为什么不能像安卓那样「置 false 就显示」

| | 安卓 | iOS 2.7.1 |
|---|---|---|
| 宿主有头像视图 | ✅ | ⚠️ 类在，但没人创建 |
| 有接线（谁 new 它） | ✅ | ❌ **0 处引用** |
| 灰度键 | ✅ `hide_assistant_avatar` | ❌ **二进制里根本搜不到这个键** |
| 修复方式 | 灰度置 false | **无解** |

**安卓是「有接线 + 被灰度关掉」，iOS 是「连接线都没有」。**

那唯一 1 处对 `DeepSeek_Chat.AvatarView` 的引用（2.6.2 的 0x1005d44a0）
是它自己 `init` 里的错误处理：

```
init(coder:) has not been implemented
Fatal error
init(frame:)
DeepSeek_Chat.InnerAvatarView
DeepSeek_Chat/AgentAvatarView.swift
DeepSeek_Chat.AvatarView
```

### 2.5 试过「自己 new 一个宿主 AvatarView」⇒ SIGTRAP

尼尼试了最直接的移植方案：既然类还在，那就自己 `alloc/initWithFrame:` 它，
塞进 `AgentMessageView`，位置尺寸全由宿主代码决定。

```objc
Class avCls = objc_getClass("_TtCC13DeepSeek_Chat16AgentMessageView10AvatarView");
id inst = [avCls alloc];
inst = [inst initWithFrame:CGRectMake(0, 0, 32, 32)];
```

结果：

```
12:19:16.302 [I][ui] [av-probe] ═══ 尝试实例化 AvatarView ═══

===== CRASH signal=5 (SIGTRAP) =====
```

**SIGTRAP** = Swift 的 `fatalError()` / `preconditionFailure()`。
说明这个类的 `init` 在 Swift 那边有前置条件，外部裸 `alloc` 必然撞上。

> 这条路封死了。代码已删除（`FDMAssistant.m` 里留了注释）。

### 2.6 最终结论

**iOS 宿主的助手头像：1.x 有，2.x 删了，且删得很干净（连灰度开关都没有）。**

⇒ 只能用「自己插一个 UIImageView」的方案（v62 已实现，真机可用）：
锚点 `AgentMessageView` 左边 24px 空隙，头像 22px 塞进去。

## 四、这一轮踩的坑

| # | 坑 | 教训 |
|---|---|---|
| 1 | 用 `strings` 找类名，2.7.1 返回 0，一度以为「类全没了」| **静态字符串 ≠ 运行时**。先跑起来再下结论 |
| 2 | 在 `MapAllCandidateClasses` 里对每个类发 `isSubclassOfClass:` | SIGTRAP。**对未初始化的 Swift 类发消息会 trap**，必须用纯 C 走 `class_getSuperclass` 链 |
| 3 | 裸 `alloc/init` 宿主 Swift 类 | SIGTRAP（`fatalError`）。Swift 类的 init 可能有前置条件 |
| 4 | 以为设备装的是 2.6.2 | 实际是 **2.7.1**（二进制大小是唯一线索：23.8MB vs 25.4MB）|
| 5 | `uiopen 'deepseek://'` | **空 deeplink 让 App 直接 SIGBUS 崩** —— 已写进铁律 |

## 六、给下次的三句话

> **1. 静态看不到 ≠ 运行时没有。**
> 2.7.1 把类名从字符串表里抹了，但 `__objc_classlist` 和运行时完全没动。
> 用 `strings` 搜不到就以为功能没了，是我这一轮最大的误判。

> **2. 对 Swift 类发消息要小心。**
> `[cls isSubclassOfClass:]`、`[cls alloc]` 都可能撞 `fatalError` ⇒ SIGTRAP。
> 遍历类表请用纯 C：`class_getSuperclass` + 指针比较。

> **3. 「曾经有过」不等于「现在能用」。**
> 旧版有 `avatar` 字段，新版删了。**删掉的功能不能靠改配置救回来**，
> 只能自己补实现。
