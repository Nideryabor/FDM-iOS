## 二、视图树实锤（不是猜的）

```
UIDropShadowView            f=(0,40 414x696)          ← sheet 从 y=40 开始
  UILayoutContainerView     bg=#000000/0.00
    UIImageView  414x696    ★FGIMG                     ← 我们贴的容器图
    UIView       414x696    bg=#000000/0.31  ★DIM      ← 我们贴的压暗
    UINavigationTransitionView
      UIViewControllerWrapperView
        UITableView  bg=#000000/0.00
          UIImageView 414x696  ★FGIMG                  ← ★ 又一张，在 table 里面！
```

两个关键事实：

1. `vc.view` **就是** `UILayoutContainerView`（sheet 容器本身），它是透明的。
   我们把它的导航栏也做成透明 ⇒ 整个页面变成"玻璃"，什么都透。
2. `UITableView` 的**子视图里**有一张 `★FGIMG` —— 那是
   `BTApplyScrollBG` 贴到"固定祖先"上的图，结果落在滚动容器内部，
   于是**跟着内容一起滚**（所以看起来像壁纸在动）。

## 三、修法（四处，都在 FDMBeauty.m）

### 3.1 导航栏：只有聊天页/列表页才透明

```objc
static BOOL BTVcWantsClearNavBar(UIViewController *vc) {
    return (BTIsChatPage(cn) || BTIsListPage(cn));
}
```

- 聊天页 / 会话列表：保持透明（壁纸要透上来，主人喜欢）
- 其它（设置 / 关于 / 个性化…）：恢复系统材质

```objc
UINavigationBarAppearance *ap = [[UINavigationBarAppearance alloc] init];
[ap configureWithDefaultBackground];   // iOS 15 真正生效的是它
navBar.standardAppearance = ap;
navBar.scrollEdgeAppearance = ap;
[navBar setBackgroundImage:nil forBarMetrics:UIBarMetricsDefault];
```

> 只设 `setBackgroundImage:` 在 iOS 15 不够 —— appearance 对象优先级更高，两个都要。

### 3.2 非聊天页：压暗兜底 0.50

分区标题是系统灰字，配亮壁纸必然糊。给非聊天页一个**最低**压暗：

```objc
CGFloat a = pct / 100.0;
if (!BTVcWantsClearNavBar(vc) && a < 0.50) a = 0.50;
```

聊天页仍然完全听配置里的 `dim`（现在是 30）。

### 3.3 摘掉「贴在滚动容器里」的背景图

每次给非聊天页贴图时，顺手遍历一遍，把落在 `UIScrollView` 内部的
`BT_BGIV_TAG` / `BT_ANCESTOR_IV_TAG` 子视图删掉：

```
[bg] DeepSeek_Chat.ProfileViewController 摘掉 1 张贴在滚动容器里的背景图
```

（有就删，没有就不动，日志只在真的删了才打。）

## 五·补、第二轮：「很黑 / 正常」的分界线（主人当场指出）

> 主人：「也不是说雷霆大黑条，就是能明显看到一个很黑和正常的分界线」

### 真凶：压暗罩被插进了表格里

`bgtree` dump 实锤（设置页）：

```
UILayoutContainerView 414x696
  UIView ★DIM 0.50                      ← 父页面（Root）插的
  UITableView 414x696
    UIView (0,-56 414x696) 0.50 黑       ← ★ 又插了一个，而且会滚！
```

**设置页的 `vc.view` 本身就是那张 `UITableView`**（`bounds.origin.y = -56` 是导航栏 inset）。
我们把压暗罩当子视图插进去 ⇒

1. 它跟着内容滚动；
2. 高度只有 696 点，滚走一部分后**下边缘暴露** ⇒ 屏幕上一条硬邦邦的水平分界线。

### 修法：两条铁律

```objc
/* ① vc.view 是滚动容器 ⇒ 绝不在它里面插覆盖层 */
if ([vc.view isKindOfClass:[UIScrollView class]]) {
    /* 摘掉历史遗留的 ★DIM / ★FGIMG，然后本层不插（父页面已有全屏压暗） */
}
```

### 第二轮之后还有一层：表格透明 ⇒ 下层内容透上来

`vc.view` 是表格且**完全透明**，下面的会话列表（"置顶61个对话"、"多巴胺越狱…"）
直接透上来，和实心深灰的导航栏拼出一条硬边。

修法：给滚动容器铺**不透明**的统一底色（背景色不参与滚动）：

```objc
static UIColor *BTSolidPageColor(void) {
    return [UIColor colorWithRed:0.109 green:0.109 blue:0.118 alpha:1.0]; // ≈ #1C1C1E
}
```

导航栏也用**同一个颜色**（`ap.backgroundColor = BTSolidPageColor()`，
并 `shadowColor = clear`），彻底消灭色差。

### 验收（像素采样，不是"看着差不多"）

```
导航栏 y=60   (28,28,30)
表格空白 y=600 (28,28,30)   ← 完全一致 ✓
列表卡片 y=200 (41,41,41)   ← 卡片本身 #282828，正常
```

改 `fdm-bg.json` 里的 `alpha` 不会重贴，必须重启 App。
现在签名里补上了 `alpha` / `chat_enabled` / `list_enabled` / `settings_enabled`。

### 第三轮：主人问「那设置的背景图怎么办」

把表格设成不透明之后，设置页的壁纸就没了 —— 主人当场发现。

**为什么不能简单设成透明**：表格透明露出来的是 Root 的**内容页**
（会话列表/聊天页），不是壁纸；因为 `UINavigationTransitionView`
那一层压在我们的 `★FGIMG`/`★DIM` 之上。

**正解：用 `backgroundView`**

```objc
UITableView/UICollectionView.backgroundView = bgv;
bgv  = [统一底色] + [UIImageView 壁纸] + [压暗层]
```

它同时满足四件事：

| 需求 | 为什么 backgroundView 能做到 |
|---|---|
| 不跟着滚 | backgroundView 是背景，不参与 content 滚动 |
| 挡住下层内容 | 它在 cell 之下、在下层 VC 视图之上 |
| 和 Root 的壁纸对齐 | frame 用 `[sv convertRect:window.bounds fromView:window]` 换算 |
| 导航栏无色差 | 导航栏保持透明，露出的就是同一张图 + 同一 alpha 的压暗 |

最后一条是关键：**导航栏透明 + 内容区放同源同位的图**，
两边的像素来自同一张图、同一个压暗 ⇒ 既没有色差，也不可能错位。

### 最终验收（像素采样）

```

内容区  y=90   (51,57,69)   ← 连续，无分界线 ✓
滚到底  y=600  (64,61,70)   ← 壁纸还在，无残影 ✓
```
