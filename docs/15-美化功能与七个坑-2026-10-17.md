## 二、⭐ 关键发现

### 2.1 宿主页面结构（文件名是最好的线索）

```
DeepSeek Chat/Pages/Session/
├─ SessionList/SessionListViewController.swift     ← 会话列表
└─ SessionMessage/MessageViewController.swift      ← 聊天页 ★
```

Swift 的 mangled 类名是 `_TtC<模块名长度><模块名><类名长度><类名>`：

```
_TtC13DeepSeek_Chat21MessageViewController      ← 21 = "MessageViewController".length
_TtC13DeepSeek_Chat25SessionListViewController  ← 25
_TtC13DeepSeek_Chat21SessionViewController      ← 21（抽屉容器，不是列表！）
```

**⚠️ 数字写错就 `objc_getClass()` 返回 nil，静默失败。**
尼尼第一版写成了 `Chat19MessageViewController`（19），结果 hook 一直没生效，
日志里连一行都没有 —— 白折腾两轮。

### 2.2 字号是纯 MMKV，零 hook

```
app.fontSize.followSystem       = "true"/"false"
app.fontSize.userPreferredLevel = "0".."4"   (small → xxLarge)
```

直接写 MMKV 就是等价于用户去「设置 › 字体大小」拖动，**最稳，零风险**，
重启 App 生效。

### 2.3 PHPickerViewController 不需要相册权限

iOS 14+ 的 `PHPickerViewController` 在**独立进程**里选图，只把选中的那张交给宿主，
所以**不用申请 NSPhotoLibraryUsageDescription 权限**。这是「不装 Filza 也能选图」的关键。

## 三、💥 七个坑（按代价排序）

### 坑 1 · `class_getInstanceMethod` 会沿继承链查找 ⇒ 改到父类

```objc
// 错误
Method m = class_getInstanceMethod(MessageViewController.class, @selector(viewDidLoad));
method_setImplementation(m, myImpl);
```

如果目标类**自己没实现** `viewDidLoad`，返回的是 **UIViewController 的那个方法**，
于是 `method_setImplementation` 把**全局 UIViewController.viewDidLoad** 换掉了：

```
⇒ 其他所有页面的 viewDidLoad 走进我们的函数
⇒ 我们只登记了目标类，BTFind 查不到它们 → 返回 NULL
⇒ 原实现一次都没被调用 → 宿主初始化全缺失 → 点任何页面都崩
```

**正确做法**：先判断「这个类自己有没有实现」，没有就 `class_addMethod` 加一个覆盖。

```objc
if (!hasOwnImplementation) {
    class_addMethod(c, sel, imp, types);   // 只影响这个类
} else {
    method_setImplementation(m, imp);
}
```

### 坑 2 · 子类 + class_addMethod ⇒ 原 IMP 指向自己 ⇒ 无限递归

```
① 父类 SessionViewController 被 hook，BTFind 记 orig = UIViewController.viewDidLoad ✓
② 子类 SessionListViewController 也 hook，但子类没自己的实现
   → class_getInstanceMethod 拿到父类的（已被换成我的函数）
   → old = myFunc  ← 就是自己！
③ BTFind(子类) 查到 orig = myFunc → 「调用原实现」= 调自己 → 爆栈
```

**修复**：hook 前检查 `old` 是不是我们自己的任何一个 wrapper，是就拒绝。

```objc
if (old == (IMP)myHook1 || old == (IMP)myHook2 || old == (IMP)myHook3) {
    return NULL;   // 防递归
}
```

### 坑 3 · 背景「插子层」会被 SwiftUI 的容器盖住

```objc
[vc.view insertSubview:bgView atIndex:0];   // 看起来在底层
```

但宿主是 SwiftUI，视图层级很深：
```
vc.view
 ├─ HostingView（不透明背景）← 把我们整个盖住
 ├─ ContainingView
 └─ ScrollView
```

**修复**：不插子层，直接改 `vc.view.layer.contents`（贴在自己身上，不参与堆叠）：

```objc
vl.contents = (__bridge id)img.CGImage;
vl.contentsGravity = kCAGravityResizeAspectFill;
vl.contentsScale = 1.0;    // ★ CGImage 已是像素，别乘 3（会缩小）
vc.view.backgroundColor = [UIColor clearColor];
```

### 坑 4 · 模态动画未结束就 present ⇒ 崩

```objc
[picker dismissViewControllerAnimated:YES completion:nil];
[top presentViewController:alert ...];    // 动画还在跑 → 崩
```

**修复**：所有后续动作放进 `dismiss` 的 completion 里。

### 坑 5 · 后台线程改 UI ⇒ 崩

```
"Modifications to the layout engine must not be performed from
 a background thread after it has been accessed from the main thread."
```

**修复**：`FDMBeautyInstall` / `FDMBeautyRefreshBackground` 入口都先判主线程，
不在就 `dispatch_async(main)` 后 return。

### 坑 6 · 遍历 `subviews` 时修改会崩

改 `backgroundColor` 可能触发布局重算，导致 `subviews` 数组变化。

**修复**：先 `[root.subviews copy]` 拿快照再遍历。

### 坑 7 · ⚠️「假崩溃」三兄弟（最坑人）

这三个现象看起来一模一样（`uiopen` 成功、进程不出现、日志空白），
但原因完全不同，**必须先分清再动手**：

| 现象 | 真因 | 判断方法 | 解法 |
|---|---|---|---|
| 起不来 + 无崩日志 + 日志空白 | **锁屏** | 日志里连「启动」都没有 | 解锁手机 |
| 起不来 + 无崩日志 + 日志空白 | **内存不足**（< 150MB） | `vm_stat \| grep "Pages free"` | 杀后台 / `tools/free.sh` |
| 起不来 + 有崩日志 | 代码 bug | 有 `.ips` | 看 faultingThread 帧 |

**关键判据**：
```bash
tail -3 $APP/fdm.log
# 有「==================== 启动 ====================」 → 模块跑了，是模块的问题
# 完全没有                                         → App 压根没启动，先解锁/腾内存
```

尼尼在这上面浪费了 4~5 轮，反复怀疑代码、回滚版本、改 hook 方案，
实际上只是**手机锁屏了**。

## 四、当前架构（背景）

不再 hook 生命周期，改用**定时巡检**：

```
启动后每 1.5s：
  遍历所有 UIWindow → rootViewController 树（深度 ≤8）
    找到 MessageViewController / Session( List )ViewController
      → 检查该 VC 的「已贴签名」（associated object）
        不同 → 贴背景 + 记录签名
  跑 40 次（60 秒）自动停
```

优点：**完全不碰宿主方法，零崩溃风险**；代价是最多 1.5s 延迟。

想要 hook 模式（实时、无延迟）可以在 `fdm-bg.json` 里设 `"hook_mode": true`
（风险自负，坑 1/2 已修但 Swift 继承链仍可能有未覆盖的情况）。
