## 二、⭐ 苹果的 sqlite 结构（这是最关键的一节）

**WCDBSwift.framework 把 sqlite3 静态编进了自己**（5.8 MB，`__TEXT` 里有完整的 sqlite 实现）。

证据：

```
WCDBSwift 的 LC_LOAD_DYLIB 依赖表：
  UIKit / Security / Foundation / libz.1 / libobjc / libc++ / libSystem / CoreFoundation
  @rpath/libswiftCore / libswiftFoundation
  ⇒ 没有 libsqlite3.dylib

但 symbols 里有：
  _sqlite3_bind_text        N_SECT (本地定义)  addr=0xdd918
  _sqlite3_bind_blob        N_SECT (本地定义)  addr=0xdd520
  _sqlite3_bind_text16      N_SECT (本地定义)  addr=0xdd920
  _sqlite3_step             N_SECT (本地定义)  addr=0xdcdac
  ...共 32 个 sqlite3_* 符号
```

### 由此推出三条铁律

1. **指针表 hook 无效**：`dlsym(RTLD_DEFAULT, "sqlite3_bind_text")` 拿到的是**系统共享缓存**那份，
   而 WCDB 用的**不是它**。`__DATA,__got` 里也没有 sqlite 槽位（不是导入符号）。
2. **Dobby 式内联 hook 是唯一路**：必须直接改 WCDBSwift 里那份函数体的前几条指令。
3. **它可能走 UTF-16**：Swift 的 `String` 是 UTF-16，WCDB 的 `Value` 绑定字符串多半用
   `sqlite3_bind_text16`，而不是 UTF-8 的 `bind_text`。

### 真实的函数体（从 WCDBSwift 里 dump 出来）

```asm
_sqlite3_bind_text @ 0xdd918:
  +0: 52800025    mov  w5, #1          ← 设置参数（标记"文本"）
  +4: 17ffff06    b    0xdd534         ← ★ 尾调用到共享实现体

_sqlite3_bind_blob @ 0xdd520:
  +0: 37f80063    tbnz w3, #0x1f, ...  ← 真正的实现体开头
  +4: 52800005    mov  w5, #5
  +8: 14000003    b    ...
```

`bind_text` 那个 `b 0xdd534` 就是**尾调用优化**：它把参数准备好，直接跳进 `bind_blob` 内部的
共享实现（0xdd520 + 0x14 = 0xdd534）。

## 三、💥 踩的 6 个坑（按代价排序）

| # | 坑 | 症状 | 教训 |
|---|---|---|---|
| **1** | **符号表偏移用错基点** | 一开 hook 就 `SIGSEGV @ strcmp` | `symoff` / `stroff` 是**文件偏移**，必须走 `__LINKEDIT` 换算：`addr = slide + linkedit.vmaddr - linkedit.fileoff + symoff`。**不能** `mach_header + stroff` |
| **2** | **只认 `__la_symbol_ptr`** | 指针表 hook 一直 0 处 | chained-fixups 时代导入指针在 **`__DATA,__got`（section type = 6）**，要按 **type** 匹配而不是名字 |
| **3** | **把尾调用 `B` 当 PC 相对指令放弃** | `bind_text` 永远挂不上 | 覆盖窗口里遇到无条件 `B`，要在跳板里**模拟这次尾调用**（跳到 B 的目标），而不是放弃 |
| **4** | **`/var/jb/usr/lib/fdm-hot.dylib` 会消失** | App 启动 `❌ 所有候选路径都失败`，**看起来却像「抹除成功」** | 部署后**必须回读验证文件存在**；日志显示"没东西"时要先确认 hook 真的加载了。**「假成功」比崩溃更难查** |
| **5** | **`if (dest) dest(data)` 会跳 -1** | 潜在的 SIGSEGV | `SQLITE_TRANSIENT` = `(void*) -1`，**不是函数指针**。清理原缓冲前必须先判 `dest == -1` |
| **6** | **Swift 类在 ObjC runtime 里方法数为 0** | xray dump 出来的 90 个类全是 `(0 方法)` | Swift 方法在 Swift vtable 里，**不受 ObjC runtime 管理**。想找 Swift 的 Hook 点只能靠静态分析符号 / CoreText / UIKit 层 |

## 四、arm64 内联 hook 的正确实现

```c
// ① 分析要覆盖的 2 条指令（固定 8 字节 = ldr x16,#8 + br x16）
for (k = 0; k < 2; k++) {
    insn = p[k];
    if ((insn >> 26) == 0x05) {          // 无条件 B = 尾调用
        target = p + k + imm26*4;         //   跳板里直接跳到 B 的目标
        break;
    }
    if (InsnIsPCRelative(insn)) return NULL;   // 其它 PC 相对 → 放弃
    tramp[k] = insn;
}

// ② 跳板 = [原指令] + ldr x16,#8 + br x16 + .quad 续跑地址
// ③ 目标函数开头改成 ldr x16,#8 + br x16 + .quad 我们的函数
// ④ sys_icache_invalidate 两边都要刷
```

`InsnIsPCRelative()` 必须覆盖：`B`(0x05) / `BL`(0x25) / `b.cond`(0x54xxxxxx) /
`LDR literal`(0x18/0x58) / `ADR`·`ADRP`(0x10/0x90) / `CBZ`·`CBNZ`(0x34/0x35) /
`TBZ`·`TBNZ`(0x36/0x37)。
