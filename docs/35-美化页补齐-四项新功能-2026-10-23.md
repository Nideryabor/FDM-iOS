## 二、⭐ 三个关键判断（决定了怎么写）

### 2.1 账号名：为什么「改网络响应」永远不生效

文档 30 记的是「存储改了（有日志），UI 仍不认 —— 宿主有内存缓存」。

**根因**：`/api/v0/users/current` 只在登录/冷启动时请求一次，
之后抽屉里的名字来自**内存里的 user model** —— 改响应再多次，那个 model 也不会重建。

**正解**：走和头像同一条路 —— hook `FooterView` 的 `layoutSubviews`，
布局完把 `nameLabel.text` 再写一遍。

```objc
Ivar iv = class_getInstanceVariable([footer class], "nameLabel");
if (!iv) { /* 兜底：找最宽的 UILabel */ }
l.text = gNameText;
```

好处和头像一样：
- 宿主自己刷新之后，下次布局又会被我们盖上去 ⇒ **不闪回**
- 完全不碰 avatar ivar ⇒ 头像和名字互不干扰
- 找不到 ivar 就安静退出 ⇒ 版本一换也不会崩

### 2.2 助手图片：宿主**根本没有** AI 头像视图

勘察结论（`strings -a` 全量扫过）：

```
ResponseFragmentView / AgentMessageCell     ← AI 回复容器
（没有任何 AssistantAvatar / BotIcon / RoleIcon）
```

DeepSeek 默认不给 AI 画头像。所以两条路：

| 方案 | 问题 |
|---|---|
| A. 等找到宿主头像再换 | 宿主一天没有，功能一天是空的 |
| B. **我们自己加一个** | 位置要自己算，但**永远有效** |

选 B。位置由「容器 bounds + 边距 + 尺寸」算出，`layoutSubviews` 末尾定位，
**不动宿主的 autolayout**。而且即使宿主将来真加了头像，我们的做法也仍然成立（只是多一个）。

### 2.3 文件快捷：为什么「填输入框」而不是「直接发」

截图里写的是「自定义上传文件后的**快捷发送**项」。

但我选了「**填进输入框**」，理由：
- 用户点一下可能只是想看看提示词长什么样
- 直接发出去 = 无法撤回（而且会消耗 token）
- 填进去之后用户可以改两笔再发

为此在 `FDMComposer.m` 加了一个公开能力：

```objc
BOOL FDMComposerFillText(NSString *text);   // 只填不发
```

## 三、四个新功能的实现要点

### 3.1 对话气泡设置（最复杂）

宿主结构（字符串实锤）：

```
_TtC13DeepSeek_Chat14UserBubbleView
_TtC13DeepSeek_Chat21UserRequestBubbleView
  ivar: bubbleView / bubbleCorner / baseCornerRadius / maskedCorners
```

**关键发现**：宿主自己就有 `bubbleCorner` / `baseCornerRadius` ——
说明圆角是**可配属性**，我们改值就行，不用重画。

三种改动分别怎么落地：

| 功能 | 实现 | 为什么 |
|---|---|---|
| 底色 | `backgroundColor = ...` | 直接改，最稳 |
| 圆角 | `layer.cornerRadius` + `masksToBounds` | 支持四角不同时用 `CAShapeLayer` mask |
| **图片底** | **关联 `CALayer`（`contents`）** | 加子视图会挤掉宿主布局；加 layer 只要跟着 bounds |

图片底最麻烦的是**缩放 + 锚点**。这里用了纯 C 内核 `FDMBubbleStyle.c`：

```c
fdmrect fdmbubble_image_rect(imgW, imgH, viewW, viewH, scale, anchor, inset);
```

30 条断言覆盖：cover / contain / stretch / tile × 9 个锚点、
NaN 输入、极端比例（1×1000 图放进 300×200）、inset 过大/负数。

然后把它翻译成 `CALayer.contentsRect`（0..1 的相对裁剪窗口，正好能表达意图）。

**为什么必须单独测**：`cover + anchor` 是「图片比容器大时裁哪边」，
`contain + anchor` 是「图片比容器小时往哪边留白」—— 两个语义共用同一个公式
`偏移 = (容器 - 图片) × 归一化锚点`，但符号相反。算错一次就是"图片跑到屏幕外"。

### 3.2 悬浮便签（最可控）

这是唯一**完全自己控制**的一块：不 hook 宿主任何方法，
只每 1.5 秒巡一次 `keyWindow`（防止宿主切页后 window 换掉）。

数据模型也抽成纯 C（`FDMNoteModel.c`，25 条断言）：

```json
{"idx":0,"min":false,"items":[{"t":"买牛奶","x":120,"y":300}]}
```

覆盖：JSON 往返 / 转义（引号、反斜杠、换行、`</script>`）/ `\uXXXX` 解码 /
垃圾输入（11 种）/ idx 越界夹紧 / 删到只剩一张时清空文字而不是变 0 张 /
拖动夹紧（允许一半出屏但拖不丢）/ NaN。

界面细节（照抄安卓 GmNoteView 的取舍）：

- **只有 ≡ 那一小块是拖动把手** —— 整条顶栏能拖会让「＋」按钮时灵时不灵
- 按钮用**纯几何符号**（`≡ ＋ ‹ › － ▣ ✕`），不用 emoji（各家机型肥瘦不一）
- 最小化 = 一颗圆球，点它回来
- 删到最后一张 = **清空文字**而不是变成 0 张（否则会出现空悬浮层）

### 3.3 文件快捷选项（宽容解析）

配置是「一行一条」的多行文本：

```
总结|帮我用要点总结这个文件
翻译|把这个文件翻译成中文
```

`FDMFileCard.c` 20 条断言，重点全在**宽容**：

| 情况 | 行为 |
|---|---|
| 没有 `\|` | 整行当按钮文字，prompt 用同样的文字 |
| 全角 `｜` | 也认 |
| `A\|a\|b` | prompt = `a\|b`（后面的 `\|` 保留） |
| 空行 / 纯空白行 | 跳过 |
| CRLF 行尾 | 正确去掉 `\r` |
| label 超 12 字符 | 按**字符**截断（不切坏 UTF-8） |
| 超过 8 条 | 丢掉后面的 |
| 一条都没解析出来 | **回退到默认三条**（不能因为手滑就让功能消失） |

### 3.4 液态玻璃上 UI + 热生效

新增设置组 `glass`：

| 键 | 值 | 说明 |
|---|---|---|
| `on` | bool（默认 **YES**） | 关 = 一条 hook 都不下 |
| `tier` | `auto` / `off` / `light` / `blur` / `refract` / `native` | 用户定档 |

新增 `FDMGlassReloadConfig()`，解决一个之前会静默失效的问题：

```
设置页写 fdm-glass.json  →  Install 读的是 fdm-debug.json  →  ❌ 不生效
```

现在**两个来源都读**，优先级 `FDMConfig`（设置页）> `fdm-debug.json`（调试通道）：

```objc
if ([c groupByID:@"glass"]) {   // UI 注册过就用 UI 的
    on   = [c boolFor:@"glass" key:@"on"];
    tier = GlassTierFromName([c stringFor:@"glass" key:@"tier"]);
} else {                        // 否则退回调试文件
    ... GlassDebugDict() ...
}
```

> 留着 `fdm-debug.json` 那条是有用的：TrollFools 注入后宿主立刻启动，
> 来不及点设置页时，改一个 JSON 就能验证玻璃到底能不能画。

## 五、⚠️ 这一轮的六个坑

| 坑 | 表现 | 解法 |
|---|---|---|
| Theos 开了 `-Werror` | 弃用 API 直接编译失败 | `#pragma clang diagnostic ignored` 局部屏蔽 |
| `keyWindow` / `.windows` 在 iOS 13 弃用 | 4 个文件都报错 | 抽成 `FDMFindBestWindow()` 一个函数，只在里面屏蔽 |
| `CALayer` 没有 `tag` | 编译期报错 | 用 `layer.name` 存字符串（顺带日志可读） |
| 传 `static UIImage*` 的地址给 `UIImage**` | ARC 下报 autoreleasing | 改成**返回值**，不要出参 |
| `FDMComposerFillText` 一开始不存在 | 链接失败 | 在 FDMComposer.m 补一个公开函数（复用已有 static） |
| 设置页写 `fdm-glass.json`，Install 读 `fdm-debug.json` | **热生效静默失效** | 两个来源都读，UI 优先 |

> 最后那条最值得记：**「配置写进去了」≠「功能读到了」**。
> 两套配置源各写各的，表面看都在工作，实际上互相不知道对方。

## 七、下次开工（真机回来第一件事）

按这个顺序，每步都能独立判断：

1. **看 4 行内核自检** —— 不出现 = 那一层算法有问题（日志给 got/want）
2. **看 4 行配置日志** —— 确认配置真的读到了（on=N 条数=）
3. **开一个功能试一个**（建议先便签，因为它最不依赖宿主）：
   - 便签不出现 ⇒ 看 `[note] 已挂到` 那行；没有 ⇒ window 没找到
   - 便签出现但位置怪 ⇒ 拖一下，看 `fdm-note.json` 里的坐标对不对
4. **气泡**：`hook 完成：我方 N` 里 N=0 ⇒ 宿主类名变了，需要 dump
5. **助手图片**：`N 个 AI 容器类` = 0 同理
6. **文件快捷**：`N 个文件容器类` = 0 同理；有但按钮不出现 ⇒ 看是不是被宿主布局盖住

## 八、给下次的三句话

> **1. 一个功能「有存储」不等于「有效果」。**
> 账号名改了半年的存储，UI 一次都没认 —— 因为真正显示的那个 label 有内存缓存。
> 判断"改了没生效"时，先问「界面上那个字是从哪来的」，而不是「存储里有没有」。

> **2. 宿主没有的视图，就自己加一个。**
> 等宿主给 AI 画头像可能永远等不到；自己在容器里插一个，位置自己算，
> 反而比"找宿主某个 ivar"更稳 —— 而且宿主将来加了我们也不冲突。

> **3. 最容易错的是算术，不是 UIKit。**
> 气泡锚点、便签夹紧，全是纯算术，都能在小窝里跑断言。
> 把"算"从"画"里剥出来，是这一轮最省时间的一个决定。
