## 〇、一句话

**两态设计**：常态 = 封面 + 歌词 + 进度 + 按钮；点歌词 → 收起播放条、封面平滑铺满底部、左上角留一个 `‹` 返回。
控件居中 · 进度圆点 28pt → 14pt。

### 1.1 关键布局原则（主人明确要求）

> 「拉长以后是图片这样，应该是进度条吸附在下面的播放控件位置，这样能显示更多歌词才对」

⇒ **常态布局从下往上算**：

```
btnY  = h - kPad - 30            ← 按钮行贴底
slY   = btnY - 6 - 22            ← 进度条吸附在按钮上方
lyric = 从 bodyY 到 slY - 6       ← 剩下的全给歌词
```

这样卡片拉高时，多出来的高度**全部变成歌词行数**，中间不会留一片空白。
（v65 之前是 `sliderY = kCoverSide + 4 = 88` 写死的，拉高就中间一大片空。）

### 1.2 手势分工

| 手势 | 位置 | 行为 |
|---|---|---|
| 单击 | 歌词区 | 常态 ⇄ 聚焦 |
| 双击 | 歌词区（聚焦态） | 切纯图 ⇄ 恢复歌词 |
| 双击 | 卡片（纯图态） | 恢复歌词 |
| 长按 0.45s | 聚焦态歌词某句 | **跳到那一句** |
| 单指拖 | 卡片空白处 | 移动卡片 |
| 单指拖 | 四角手柄 | 改大小 |
| 滑动 | 聚焦态歌词区 | **滚歌词（3 秒锁定，不拖卡）** |
| 双指捏 | 任意 | 也能缩放 |

⚠️ 单击必须 `requireGestureRecognizerToFail:` 双击 + 长按。
⚠️ 卡片的 pan 手势 `shouldReceiveTouch:` 要避让：手柄 / 歌词表 / 搜索表 / 输入框 / 按钮 / 进度条。

## 二、iOS 实现要点（`FDMMiniBar.m`）

| 项 | 做法 | 踩的坑 |
|---|---|---|
| 居中按钮行 | 先量总宽 `44+52+44+32+32+8×4 = 236`，再 `x=(w-236)/2` | 原来是从右边往左叠，必然右对齐 |
| 小圆点 | `UIGraphicsImageRenderer` 画 14pt 圆 → `setThumbImage:` | **UISlider 没有 thumb 尺寸属性**，只能换图 |
| 聚焦态 | `setFocusMode:` 里改 hidden + `setNeedsLayout` + 动画块 | 直接改 frame 不会动，必须 `layoutIfNeeded` 在动画块内 |
| 返回键 | 独立 `_backBtn`（`‹`，20pt），与 `♪`/`✕` 互斥显示 | 和 `♪` 抢同一个左上角位置，必须互相 hidden |
| **封面当背景** | 聚焦时 `_playPage.frame=(0,0,w,h)` + `_cover.frame=(0,0,w,h)` | ★★ `_cover` 是 `_playPage` 的子视图，只改 cover 的话它铺不到标题区（被 `bodyY` 挡住），**必须先把 `_playPage` 撑满** |
| **暗膜** | `CAGradientLayer`（上 0.62 → 中 0.28 → 下 0.72）夹在 cover 和歌词之间 | 纯色会把封面糊死；且 `CAGradientLayer` **不跟 frame 自动变**，layout 里要手动同步 |
| 四角手柄 | 4 个 22×22 透明 view + 里面 10pt 小圆点，`tag=0..3` | 手柄贴内边 `ins=1`，否则被 `clipsToBounds` 的圆角裁掉 |
| **四角缩放算法** | 记 `_dragBase`(起始 frame) + `_dragStart`(起始点)，每次算**总位移** | ★ 别用"累加增量"：夹到最小尺寸后往回拖会有一段死区，手感很怪 |
| 手柄 vs 整卡拖动 | `_pan.delegate` + `shouldReceiveTouch:` 判 `v.tag<=3` 就返回 NO | 否则摸到角上会变成"整卡被拖走" |
| 尺寸记忆 | 存档 `{x,y,w,h,sw,sh}`；**没有 sw/sh 就是老格式 ⇒ 尺寸用默认** | ★ 老格式 w/h 存的是屏幕尺寸（414×736），当卡片尺寸读会把卡撑爆 |

### 2.1 四角缩放的对角固定规则

| 拖哪个角 | 固定的是 | 变化的 |
|---|---|---|
| 左上 TL | 右下 | `origin` + `size` |
| 右上 TR | 左下 | `origin.y` + `width` + `height` |
| 左下 BL | 右上 | `origin.x` + `width` + `height` |
| 右下 BR | 左上 | 只变 `size` |

尺寸夹紧 `240~560` 宽 / `150~560` 高，四角一致。

## 三、安卓反向移植评估

### 3.1 好消息：安卓那边**结构已经对上了**

`GmMiniBarView.java`（1,051 行，`FrameLayout` 手画）本来就是：

```
┌ 播放页 ─────────────────────┐    ┌ 搜索页 ──────────┐
│ 封面 │ 曲名&歌手 ✕          │    │ [输入] [搜]      │
│      │ 歌词                 │    │ 结果列表         │
│ 进度条                       │    └─────────────────┘
│ ♪ ◀◀ ▶ ▶▶ ↻                │
└────────────────────────────┘
```

**要改的只有四件**，全在 `GmMiniBarView` 里，**不动 GmMusicPlayer**：

| # | 改什么 | 安卓怎么写 | 难度 |
|---|---|---|---|
| 1 | 按钮行居中 | 现在是 `LinearLayout` 顺序加 → 改成算总宽再 `setPadding` 或加左右 `Space` 权重 1 | 易 |
| 2 | 进度圆点变小 | `SeekBar` 的 `setThumb(new ShapeDrawable(OvalShape))` + `setThumbOffset` | 易 |
| 3 | 点歌词进聚焦态 + **封面当背景** | 给歌词 `TextView` 设 `OnClickListener`，进/出聚焦；聚焦时 `slider.setVisibility(GONE)` + 按钮行 `GONE`；**封面 `ImageView` 提到最底层并 `MATCH_PARENT`**，歌词 `TextView` 保持在上层，中间插一个 `GradientDrawable` 暗膜 | 中 |
| 4 | 左上角返回键 | 聚焦态时把 `♪` 隐藏、显示 `‹`；`‹` 的 `OnClickListener` ⇒ 退出聚焦 | 易 |
| 5 | **四角拖拽缩放** | 四角各放一个 `View`（22dp）+ `OnTouchListener` 处理 `ACTION_MOVE`；按"对角固定"改 `LayoutParams.width/height` 和 `x/y` | 中 |

### 3.1 安卓四角缩放的坑（比 iOS 多）

1. **`FrameLayout.LayoutParams` 不能像 iOS 那样直接改 frame**：
   要 `lp.width = nw; lp.height = nh; view.setLayoutParams(lp); view.setX(...); view.setY(...)`，
   而且 `setX/setY` 和 `layoutParams.leftMargin` 会打架 —— **统一用 `setX/setY`**，别混用。
2. **父容器如果是 `DecorView`**，`setX/setY` 是相对 DecorView 的，坐标算对了就行。
3. 必须 `requestLayout()`，否则改了 `lp` 不生效。
4. 手柄在角上会被圆角 `clipToOutline` 裁掉 → 手柄贴内边 1dp，或者给手柄单独放一个不裁剪的父层。

### 3.2 需要留意的三点

1. **动画要一起动**：安卓如果只 `setVisibility(GONE)` 再 `layout()`，会「瞬移」。
   必须用 `ViewPropertyAnimator` 或者 `TransitionManager.beginDelayedTransition(root)`。
   → iOS 那边是 `UIView` 动画块天然平滑，安卓要**显式**做。

2. **封面要换 ScaleType**：
   常态是小方图（`CENTER_CROP`），聚焦铺满底部会变成横的（还是 `CENTER_CROP`，但会被裁）。
   如果主人想要「不裁切」，聚焦态得换 `FIT_CENTER` + 背景取主色。

3. **手势会不会和宿主抢**：
   安卓 mini bar 挂在宿主 `decorView` 上，歌词区点一下进聚焦 —— 这个点击**不会**和
   宿主的 Compose 手势冲突（因为 mini bar 在最上层且自己 `setClickable(true)`）。
   ⚠️ 但 `SeekBar` 的拖动要确认不触发宿主的侧滑返回。

### 3.3 结论

**可以移植，而且是纯 UI 改动，风险低。**
工作量估计：`GmMiniBarView.java` 改 150~200 行，`GmMiniBar.java` 不用动。
不需要碰任何 hook、不需要碰 `GmMusicPlayer`。

> 建议顺序：先做 ①②（10 分钟，纯参数），真机看一眼；再做 ③④（要调动画曲线）。

## 五、给下次的三句话

> **1. 用户的"排版喜好"必须逐字抄进文档。**
> 这次如果只写"改成居中了"，下次就没人知道"居中"是相对什么居中、间距多少。

> **2. 老存档是炸弹。**
> 同一个键 `w/h` 换了语义（屏幕尺寸 → 卡片尺寸），旧数据就会把 UI 撑爆。
> 加个 `sw/sh` 版本标记，没有就退回默认值 —— 比写迁移脚本省事。

> **3. 手势叠加先定"谁等谁"。**
> 单击 + 双击共存，必须 `requireGestureRecognizerToFail`；
> 单指拖 + 双指捏天然不冲突（`maximumNumberOfTouches` 不同）。
