## 一、★ 富文本不渲染：渲染成功了，但被丢掉

### 1.1 矛盾的事实

日志里明明有：

```
23:39:27.639 [rich] ★ 裸标签渲染 726 → 668 字
```

`726 → 668`，少了 58 个字（正好是所有标签的长度）——
**渲染函数跑通了，返回也正确**。

但界面上标签还在。

### 1.2 病根：宿主走的不是 `setAttributedText:`

```
宿主（Swift）：
    NSAttributedString(string: 原文)          ← ★ 走这里
    textView.attributedText = ...
```

我们 hook 了两条路：

| Hook | 原行为 |
|---|---|
| `-[UILabel/UITextView setAttributedText:]` | ✅ 会渲染富文本 |
| `-[NSAttributedString initWithString:]` | ❌ **只删 ⟦FDM⟧ 标记，不渲染** |

宿主走的是第二条 ⇒ 渲染白做了。

> 这也解释了为什么 `[sug-dbg]` 一条日志都没有：
> 建议按钮那段代码限定 `isKindOfClass:[UILabel class]`，
> 而 AI 正文是 `DSFixedLineHeightTextView`（UITextView 子类）。

### 1.3 修法：两条路都补上渲染

#### ① `initWithString:` —— 只能给纯字符串

```objc
if ([s rangeOfString:@"<"].location == NSNotFound) return 原样;

if (s.length >= 12) {
    NSAttributedString *rich = FDMRichRenderBare(probe);
    if (rich && ![rich.string isEqualToString:s]) {
        use = rich.string;      // ★ 只能取字符串，样式这里拿不到
        didRich = YES;
    }
}
if (!didRich) use = FDMStripMarks(s);   // 原逻辑兜底
```

**局限性**：`initWithString:` 返回的是 `NSAttributedString`，
但我们只能传一个纯字符串进去 ⇒ **颜色/bold 拿不到**，只有标签被去掉。

#### ② `initWithString:attributes:` —— **能保留样式**

这条更好，因为我们手上就有宿主给的 `attr`：

```objc
NSString *s = ...;
NSAttributedString *rich = FDMRichRenderBare(probe);   // probe 用宿主的 attr 当底

NSMutableAttributedString *m = [rich mutableCopy];
/* ★ 字体只取宿主的字号，但保留 rich 的 bold trait —— 
 *   否则宿主的字体（比如 15pt）会被 rich 里写死的 16pt 覆盖 */
[m enumerateAttribute:NSFontAttributeName inRange:NSMakeRange(0, m.length) options:0
           usingBlock:^(UIFont *f, NSRange r, BOOL *stop) {
    CGFloat size = hostFont.pointSize;
    UIFont *nf = (f.fontDescriptor.symbolicTraits & UIFontDescriptorTraitBold)
        ? [UIFont boldSystemFontOfSize:size]
        : [UIFont systemFontOfSize:size];
    [m addAttribute:NSFontAttributeName value:nf range:r];
}];
return [[NSAttributedString alloc] initWithAttributedString:m];
```

### 1.4 极高频方法的性能闸

`initWithString:` 每秒可能调用上千次，闸必须**便宜**：

```
① gStReent 防重入          ← 已有的
② s.length < 6 直接走      ← 已有的
③ ！[s containsString:@"<"] 直接走    ← ★ 新增，这一步最便宜且能挡掉 99%
④ s.length < 12 不尝试渲染（太短不可能是正文）
⑤ FDMRichRenderBare 内部还有 FDMRichMaybeAffected 快速闸
```

## 四、给下次的三句话

> **1. 「渲染成功了但界面没变」= 返回值被丢掉。**
> 先去日志确认渲染函数有没有跑（有 `726 → 668 字` 就是跑了），
> 然后去找**宿主走的到底是哪条路**。
> 别一上来就怀疑解析逻辑 —— 解析逻辑往往是对的。

> **2. 同一个功能要点齐所有入口。**
> `setAttributedText:` 和 `initWithString:` 是两条独立的路，
> 一条改了另一条没改，就等于没改（对宿主来说）。
> 加新能力时先想：**宿主可能从几个门进来？**

> **3. 调试开关用完要清。**
> `music_autoplay: true` 是我调试播放链路时留下的，
> 结果主人每次启动都被自动放歌。调试开关请一次性解决后立刻删。
