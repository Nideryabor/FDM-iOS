> **结论：历史干净，还没推上远端，现在改正好。**
>
> ⚠️ 中途还闹了个笑话：第一次扫 `.git/` 报「命中」，
> 结果是我把 `grep ... | head -5` 当 `if` 条件了 —— 管道的退出码来自

## 二、改成了什么

### 2.1 一个 `.env`（唯一存放口令的地方）

```bash
# /workspace/ios-port/.env   ← 600 权限，已 gitignore
IPHONE_HOST=192.168.1.6
IPHONE_PORT=2222
IPHONE_USER=mobile
IPHONE_PW=********          ← 唯一一处
IOS_MCP_HOST=192.168.1.6
IOS_MCP_PORT=8090
APP_DOCS=/var/mobile/Containers/Data/Application/<UUID>/Documents
```

同时提供 `.env.example`（模板，可入库，值全是占位符）。

### 2.2 两个加载器

| 文件 | 给谁用 |
|---|---|
| `tools/_env.sh` | shell 脚本 |
| `tools/env.py` | Python 工具（`from env import ENV`） |

两者读**同一个** `.env`，行为一致。

`tools/_env.sh` 的三条设计原则：

1. **只在本项目里找**（`_ENV_ROOT/.env`），不做跨项目 fallback
   —— 跨目录兜底会让「别的项目复制了脚本」意外读到这边的主机/口令，
   排查起来极其费解。
   要显式指定别处：`FDM_ENV=/path/to/.env ./tools/xxx.sh`
2. **关键项缺失就报错退出**，给出可照抄的修复步骤
3. **绝不回退到任何内置默认口令** ——
   「悄悄用旧密码」比「直接失败」危险得多

### 2.3 改动的脚本（10 个）

```
tools/dep.sh       硬编码 → . "$(dirname "$0")/_env.sh"
tools/deploy.sh    同上
tools/free.sh      同上
tools/iphone.sh    同上（去掉了 :-默认值 兜底）
tools/mcp.sh       主机从 .env 推导
tools/mcp2.py      HOST/PORT 从 env.ENV 读
tools/wd.py        WebDAV 地址从 .env 推导
tools/sync.sh      同上
tools/pull.sh      同上
tools/cyc.sh       ★ 顺带加了锁屏兜底（见下）
```

### 2.4 `cyc.sh` 的额外收获

改造中途撞上设备锁屏，发现 `cyc.sh` 的第 3 步（回读校验）和
第 7 步（捞日志）都只走 MCP，而 **MCP 的 `run_command` 在锁屏时会被封**。

加了 SSH 兜底：

```bash
device_size() {
  # ① 先走 MCP（快）
  # ② 拿不到 → 走 SSH（锁屏不影响）
}
```

日志步骤还多一层判断：MCP 返回的如果是 `{"blocked": true, ...}`
这种提示 JSON（不是正文），也判定失败并转 SSH。

实测：设备锁屏状态下 `bash tools/cyc.sh -s` 全 7 步通过。

## 五、给下次

> **1. 口令只该有一个家。**
> 散在 4 个脚本里，等于「有 4 次机会泄漏」，而且改密码要改 4 处。

> **2. 「悄悄回退到默认值」是安全设计里最糟的一种。**
> 宁可启动失败并打印修复步骤，也不要让人以为配好了、其实用的是旧密码。

> **3. 判空别用管道当条件。**
> `if cmd | head; then` 永远为真。用 `$(cmd | wc -l)`。

> **4. 扫历史要七道都过。**
> 分支 / tag / stash / 可达对象 / 悬空对象 / pack 二进制 / loose zlib。
> 只看 `git log -S` 会漏掉悬空提交和 pack 里的明文。
