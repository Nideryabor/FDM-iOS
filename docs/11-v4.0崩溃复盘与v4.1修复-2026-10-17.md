# 11 · v4.0 崩溃复盘 + v4.1 修复

> 2026-10-17 · 尼得亚伯 🐲
> 产物：`out/FDMProbe-v4.1.dylib`
> 崩溃日志：`DeepSeek Chat-2026-10-17-091128.ips`

---

## 〇、现象

第一次启动（pid=8733）后 **7 秒崩溃**，第二次启动（pid=8735）正常。

`fdm.log` 在 `09:11:26.966` 戛然而止，最后一条是 BLOB patch 的覆盖列表。

---

## 一、⭐ 根因：**栈溢出（无限递归）**

`crash.ips` 解析结果：

```
exception    : EXC_BAD_ACCESS / SIGILL
subtype      : KERN_PROTECTION_FAILURE
vmregioninfo : STACK GUARD（撞到栈保护页）
termination  : Illegal instruction: 4

faultingThread = 0  (com.apple.main-thread)
  # 0  libobjc.A.dylib    objc_storeStrong
  # 1  FDMProbe-v4.dylib  my_getData
  # 2  FDMProbe-v4.dylib  my_getData
  # 3  FDMProbe-v4.dylib  my_getData
  ...（一直递归到 #24+）
```

### 为什么会递归

`Swap()` 的实现（v4.0）：

```objc
static IMP Swap(Class C, const char *sel, IMP imp) {
    Method m = class_getInstanceMethod(C, sel_registerName(sel));
    IMP old = method_getImplementation(m);   // ← 关键
    method_setImplementation(m, imp);
    return old;
}
```

而 `HookMMKV()` **被调用了两次**（构造函数 + 3s 阶段）：

```
第 1 次：old = MMKV 原始实现     → o_getData = 原 IMP      ✅
第 2 次：old = my_getData（已换）→ o_getData = my_getData  ❌ 灾难
```

于是：

```
my_getData(...)
  → 调 o_getData(...) = my_getData(...)
    → 又调 o_getData(...) = my_getData(...)
      → ... 无限递归 → 栈溢出 → SIGILL
```

---

## 二、⭐ 修复（三重保险）

### ① `Swap()` 幂等

```objc
IMP old = method_getImplementation(m);
if (old == imp) return NULL;        // ★ 已经是我们的了，别动
method_setImplementation(m, imp);
return old;                          // ★ 只有真换了才返回原 IMP
```

### ② `HookMMKV()` 只执行一次

```objc
static BOOL done = NO;
if (done) return;
...
done = YES;

/* ★ 保命检查：任何"原 IMP"等于我们自己的实现 → 立刻退回 */
if (o_getData == (IMP)my_getData || ...) {
    FLOGE(FC_MMKV, @"!! 检测到自引用，放弃 MMKV 挂钩");
    o_getData = o_getString = o_getObj = NULL;
    o_setData = o_setObject = NULL;
    return;
}
```

### ③ 每个 `my_*` 内的自引用检查

```objc
static id my_getData(id self, SEL _cmd, id key) {
    if (gDepth == 0 && IsBlobKey(key) && gLastModBlob) { ...; return gLastModBlob; }
    if (!o_getData || o_getData == (IMP)my_getData) return nil;   // ★ 保命
    return ((id(*)(id,SEL,id))o_getData)(self, _cmd, key);
}
```

### 教训

| # | 铁律 |
|---|---|
| 1 | **`Swap/hook` 必须幂等** —— 重复挂会让"原函数指针"指向自己 → 无限递归 |
| 2 | **"只挂一次"要有显式标志**，不能靠调用方自觉 |
| 3 | **wrapper 内加自引用检查** —— 保命，代价是每帧一次指针比较 |
| 4 | **每个 `my_*` 都要有保命路径**，别指望上游不出错 |

## 三、顺带修的 UI 问题（用户反馈"内容不全"）

### 现象
截图里标题被截断：
```
置顶数...       10
最大输...       50
最大上...   104857600
拍照压...      0.8
最大重...      600
```

### 原因
`UITableViewCellStyleSubtitle` + `accessoryView` 放了个 **240 宽的 UITextField** → 把标题挤没了。

### 修复
Int/String 类型**不再用内嵌输入框**，改成：
```
标题（完整显示）        当前值（右侧蓝色 label，130 宽）
                        ↓ 点击
                   弹出输入框编辑
```
标题从此完整。

## 四、新功能：支持"服务端未下发的键"

### 问题
6 个键改不了：
```
conversation_search_enabled        thinking_auto_fold_enabled
copy_text_without_markdown_syntax  pinned_session_limit
voice_input_enabled                disable_single_dollar_latex
```

### 原因
```
blob   = 服务端本次实际下发的 59 项   ← 只有这些能改
键表   = 宿主二进制里认识的 66 条键
→ 键在键表但不在 blob = 服务端没下发 → 写不进去
```

### 修复
新增开关 **`允许添加未下发的键`**（默认开）：
```objc
} else if (gAllowNewKeys) {
    /* 服务端没下发，但宿主二进制认识 → 凭空加进 blob（id 用 -1） */
    st[k] = [@{@"id": @(-1), @"value": gPatch[k]} mutableCopy];
    ok++;
}
```

**风险**：宿主可能严格校验 id 而不认（那就无效，**不会崩**）。
**收益**：6 个键有机会生效。

## 七、其他观察

从崩溃日志看，**FLog 的崩溃处理器没来得及写**（日志停在崩溃前 1.4 秒）。

原因：`FLogSignalHandler` 里用了 `NSFileHandle` / `@autoreleasepool` —— **不是 async-signal-safe**，在信号上下文里可能直接挂掉。

**下一版改进**：信号处理里改用 POSIX `write()` 直接写"崩溃标记"，不用 Objective-C。
