# 51 · 富文本"渲染一瞬又变裸" + 自动播放开关（v75）

> 2026-10-25 · 尼得亚伯 🐲
> 主人：「这次我注意到标签成功渲染了一瞬间又变回裸的，顺便把自动播放做成开关功能吧」

---

## 〇、一句话

**渲染成功了，但宿主紧接着用 `setText:` 把它盖掉了。**
修法：在 `setText:` 里也做渲染，但**必须保持在重入锁内**调 `setAttributedText:`——
否则无限递归 → 栈溢出 → SIGSEGV（第一次部署上去就是这么崩的）。

---

## 一、「渲染一瞬又变裸」的真相

### 1.1 主人这个观察太关键了

「成功渲染了一瞬间」= **我们的渲染代码是对的**。
「又变回裸的」= **之后被覆盖了**。

这一句话直接把排查范围从「渲染逻辑」缩小到「调用顺序」。

### 1.2 日志证据

```
23:44:21.014 [rich] ★ 裸标签渲染 130 → 100 字
23:44:21.035 [rich] ★ 裸标签渲染 132 → 102 字     ← 字数在涨 = 流式输出
23:44:21.064 [rich] ★ 裸标签渲染 150 → 108 字
23:44:21.097 [rich] ★ 裸标签渲染 154 → 112 字
```

`130 → 132 → 150 → 159 → 163`：AI 在**流式吐字**，每来一段就重新设一次。

### 1.3 真实流程

```
① 宿主 setAttributedText: 原文
   → 我们渲染 → 设回渲染结果 → **屏幕上出现彩色**（那一瞬间）

② 宿主 setText: 原文（下一段流式数据）
   → 而 UILabel.text 和 .attributedText 是**互斥**的
   → 设 text 会**清掉所有 attributes**
   → 变回裸标签
```

我们 hook 了两条路，但 `st_setText` 只删 `⟦FDM⟧` 标记、**不渲染**。

### 1.4 修法

```objc
static void st_setText(id self, SEL _cmd, NSString *text) {
    ...
    BOOL hasTag = ([text rangeOfString:@"<"].location != NSNotFound);
    BOOL canAttr = [self respondsToSelector:@selector(setAttributedText:)];

    if (hasTag && canAttr && text.length >= 12) {
        if (!BTIsUserBubble((UIView *)self)) {     // 用户气泡只删不渲染
            gStReent = 1;
            NSAttributedString *rich = ...;        // 用控件当前字体当底渲染
            if (rich && ![rich.string isEqualToString:text]) {
                [(id)self setAttributedText:rich]; // ★★ 见下面那个坑
                gStReent = 0;
                return;
            }
            gStReent = 0;
        }
    }
    // 兜底：只删 ⟦FDM⟧ 标记
}
```

## 二、★★ 血的教训：无限递归 → SIGSEGV

### 2.1 第一次的写法（错的）

```objc
gStReent = 1;
rich = FDMRichRenderBare(probe);      // 渲染
gStReent = 0;                         // ← 这里就清了！

if (rich) {
    [(id)self setAttributedText:rich]; // ← setAttributedText 内部会回调 setText:
    return;                            //   而 gStReent 已经是 0 ⇒ 重入！
}
```

调用链：

```
setText:
  → 渲染
  → setAttributedText:
      → 内部回调 setText:          ← 重入，因为 gStReent = 0
          → 渲染
          → setAttributedText:
              → 回调 setText:
                  → ...（无限）
```

⇒ **栈溢出 ⇒ SIGSEGV ⇒ 整个 App 被杀**。

### 2.2 崩溃现场

```
23:47:01.838 [W][ui] [glass] 当前档位 T0-OFF ⇒ 不装 hook

===== CRASH signal=11 (SIGSEGV) =====
```

日志停在 glass 安装完成之后，**任何日志都没有**——
因为栈溢出是不给机会写日志的。

### 2.3 修法：把调用锁在重入区内

```objc
gStReent = 1;
rich = FDMRichRenderBare(probe);

if (rich && ![rich.string isEqualToString:text]) {
    [(id)self setAttributedText:rich];   // ★ 仍在 gStReent=1 内
    gStReent = 0;                        // ★ 之后才清
    return;
}
gStReent = 0;
```

## 三、自动播放做成开关

### 3.1 之前的状态

```json
// Documents/fdm-debug.json（我调试时留下的）
{"music_autoplay": true}
```

**这是个调试开关**，藏在 debug json 里 —— 主人根本找不到地方关。

### 3.2 现在

设置 → 美化 → 音乐播放 → **「打开 App 自动播放」**（默认关）

```objc
F(@"autoplay", @"打开 App 自动播放", FDMFieldTypeBool, @NO,
  @"开 = 每次启动自动接着上次那首放（从上次的进度开始）\n"
  @"关 = 要你自己点播放 —— **推荐**，不然一开 App 就出声\n"
  @"⚠️ 重启 App 生效"),
```

语义改进：开启后**用存档里的 `idx`**（接着上次那首），而不是从第 0 首开始。

```objc
int at0 = gQ.idx;
if (at0 < 0 || (size_t)at0 >= gQ.count) at0 = 0;
```

同时把 `fdm-debug.json` 里的 `music_autoplay` 残留清掉了。

## 五、给下次的三句话

> **1. 「渲染一瞬又变回」这个观察，价值顶十个日志。**
> 它把问题从「渲染逻辑对不对」直接定位到「谁把它盖掉了」。
> 用户描述的**时序**（一瞬间 / 之后 / 又）往往比任何技术细节都准。

> **2. 在 hook 里调用**同一个族**的另一个方法，必须锁在重入区内。**
> `setText:` 里调 `setAttributedText:`，而后者内部会回调前者 ——
> 这是 Cocoa 里非常常见的成对关系。
> **清锁的时机错了 = 无限递归 = 栈溢出 = 没有任何日志的 SIGSEGV。**

> **3. 调试开关用完立刻删，或者直接做成正式配置项。**
> `music_autoplay` 藏在我调试时的 debug json 里，
> 结果主人每次开 App 都被自动放歌，还找不到地方关。
> **能影响用户行为的开关，就不该只存在于 debug 配置里。**
