## 二、⭐ MMKV 二进制格式（这次最值钱的东西）

用真实 `mmkv.default`（262144 字节）逆向出来的，**官方文档没有这些细节**。

### 2.1 顶层结构

```
[varint keyLen][key][varint outerLen][varint innerLen][value]
```

### 2.2 实测有两种变体

```
格式 A（未登录/早期）：  95 02  80  93 02  {json}
                              ^^  ^^  ^^^^^
                          outer tag inner  ← 中间有个 0x80 类型标志

格式 B（登录后）：        95 02  93 02  {json}
                              ^^  ^^^^^
                          outer inner
```

**真实字节**（key@43414，登录前）：

```
0b  "currentUser"   82 05  80  80 05  7b 22 73 65...
^^                   ^^^^^  ^^  ^^^^^
keyLen=11            outer  tag  inner
```

**真实字节**（key@42835，登录后）：

```
0b  "currentUser"   95 02  93 02  7b 22 61 72 65 61...
^^                   ^^^^^  ^^^^^
keyLen=11            outer  inner
```

### 2.3 varint = LEB128

```python
v = 0; shift = 0
while True:
    b = buf[off]; off += 1
    v |= (b & 0x7F) << shift
    if not (b & 0x80): return v, off
    shift += 7
```

`0x95 0x02` → `(0x15) | (0x02 << 7)` = 21 + 256 = **277**
`0x93 0x02` → 19 + 256 = **275**

### 2.4 不要信长度字段，用花括号配对

实测 `inner` 和实际值长度**差 1~2 字节**（MMKV 的长度语义和公开文档不符）。
**最稳的定位**：

```python
vstart = inner 之后第一个字节（必须是 '{'）
# 花括号配对（处理字符串内转义）
depth = 0; in_str = False; esc = False
for q in range(vstart, ...):
    ch = buf[q]
    if esc: esc = False; continue
    if ch == 0x5C: esc = True; continue        # 反斜杠
    if ch == 0x22: in_str = not in_str; continue    # 引号
    if in_str: continue
    if ch == 0x7B: depth += 1
    elif ch == 0x7D:
        depth -= 1
        if depth == 0: vend = q + 1; break
```

然后 `json.loads(buf[vstart:vend])` 校验一遍，过不了就跳过这个候选。

### 2.5 ⚠️ MMKV 是 mmap 定长文件

```
mmkv.default     262144 字节（256KB，固定）
mmkv.default.crc 16384 字节
```

**总长度绝对不能变**。值变长要整体后移 + 尾部补 0；
放不下就必须拒绝（截断 = 毁掉整个文件）。

### 2.6 ⚠️⚠️ CRC 是最大的雷

**尼尼删掉 `.crc` 想让 MMKV 重算，结果宿主判定文件损坏，重建了 MMKV ⇒ 主人的登录态掉了。**

CRC 文件结构（16384 字节 = 4096 × uint32，但只有前 10 项非零）：

```
[0]  0x43AA7093   魔数
[1]  4            块数
[2]  2            itemSize
[7]  0x15387      第一块长度
[8]  4            第一块 CRC 数
[9]  0xd1539442   第一块 CRC
```

**正确做法**：改完**不要删 crc**，让 MMKV 自己在下次写入时刷新。
只有明确知道在干什么时才用 `--renew-crc`。

## 四、为什么改了存储但界面不变

实测证据链：

1. **存储层确实改成功了**
   ```
   /tmp/cur.default:  mobile = '尼得亚伯'   ← 从设备 pull 下来的真实文件
   ```

2. **Hook 也确实命中了 6 次**
   ```
   [mmkv] [user] ★ currentUser 改名 → 「尼得亚伯」（1 处，288→289 B）
   ```

3. **但界面还是手机号**

⇒ 说明：

| 可能 | 判断 |
|---|---|
| 宿主启动时把 `currentUser` 读进内存，之后一直用内存副本 | **最可能** |
| 宿主有独立的 account 缓存（另一处存储 / 服务端拉取） | 可能 |
| 抽屉的账号名另有数据源（如 `/users/current` 响应） | 可能（但启动时不请求） |

**下一个方向**：
- 不再折腾 MMKV，改 hook **具体渲染账号名的那个 UILabel/Text**
- 或者 hook `/api/v0/users/current` 的**响应**（需要先让它真的请求一次）

## 五、试验过程中搞坏的（已修复）

| 事故 | 原因 | 后果 | 修复 |
|---|---|---|---|
| **登录态丢失** | 删了 `mmkv.default.crc` | 宿主重建 MMKV，`settingsToken` 等键丢失 | 主人重新登录 |
| App 起不来（多次） | 内存不足（iPhone 7P 只有 2GB） | 无崩溃日志 + 进程不出现 | `tools/free.sh` 清理后台 |

> **教训**：动别人的存储 = 动别人的命。改之前必须先备份**整个目录**
> （含 `.crc`），而且改完不要删校验文件。

## 八、给下次的一句话

> **改别人的存储，先问「它有几层缓存」。**
>
> MMKV 只是第一层。宿主读过之后会放进内存，
> 甚至可能还有一份从服务端拉的副本。
> 改磁盘 ≠ 改界面 —— 中间可能隔着两个缓存。
>
> 而且 **`.crc` 不能删**。删了不是"让它重算"，
> 是"告诉它文件坏了" —— 它会直接丢数据。
