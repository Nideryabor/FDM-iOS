## 二、推送路径：GitHub HTTPS 全挂，走 SSH over 443

### 症状

```
fatal: unable to access 'https://github.com/...': 
       GnuTLS recv error (-110): The TLS connection was non-properly terminated.
```

### 排查

| 检查 | 结果 |
|---|---|
| TCP 443 各 IP | ✅ 都通（140.82.112/113/114.3、20.205.243.166） |
| `/etc/hosts` 换 IP | ❌ 全试过，仍然 `-110` |
| `curl https://github.com` | ❌ 超时 / 无响应 |
| `curl https://api.github.com` | ✅ **200** |
| `openssl s_client github.com:443` | ❌ 握手无输出 |
| `ssh.github.com:443` TCP | ✅ **通** |

⇒ **TLS 层被阻断，但 SSH 通道没被拦。**

### 方案

```bash
# 1. 生成专用 deploy key
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_fdm -N '' -C 'fdm-ios-deploy'

# 2. 用 api.github.com 加 key（API 通）
curl -X POST -H "Authorization: token $GH_TOKEN" \
     https://api.github.com/repos/Nideryabor/FDM-iOS/keys \
     -d "{\"title\":\"...\",\"key\":\"$(cat ~/.ssh/id_ed25519_fdm.pub)\",\"read_only\":false}"

# 3. ssh config：github.com → ssh.github.com:443
cat > ~/.ssh/config <<EOF
Host github.com
  HostName ssh.github.com
  Port 443
  User git
  IdentityFile ~/.ssh/id_ed25519_fdm
  StrictHostKeyChecking no
  UserKnownHostsFile /dev/null
EOF

# 4. remote 换成 SSH，push 正常
git remote set-url origin git@github.com:Nideryabor/FDM-iOS.git
```

**以后推这个仓不用 token** —— SSH deploy key 长期有效。

## 三、发版流程（TrollFools 注入版）

### 3.1 编译

```bash
cd src/FDMProbe5
source /workspace/ios-port/env.sh
make clean && make TROLL=1        # TROLL=1 才把 install_name 改成相对路径
```

**必须校验** `install_name`：

```bash
llvm-objdump-18 -p FDMProbe.dylib | sed -n '/LC_ID_DYLIB/,+2p'
# 期望：name @executable_path/Frameworks/FDM.dylib
```

> ⚠️ `pack-troll.sh` 的第 ④ 步会「换回绝对路径重编」——
> 如果只想要注入版，别用那个脚本，直接 `make TROLL=1` 后手工取产物。

### 3.2 发之前**先验**

把要发的那个二进制装到设备的 `TweakInject/FDM.dylib` 跑一遍，
确认日志里有这三行才发：

```
[cfg] 功能注册完成：26 页 / 266 项
[sys] FDM v7.1 已加载  pid=xxxxx
[inject] [dj] 点歌说明已拼进系统提示词（261 字）
```

**不是编出来就发。** 万一 install_name 或签名有问题，发出去就是一堆「装了没反应」。

### 3.3 打包

```
dist/FDM-v80-trollfools/
├── FDM.dylib              1,825,664 B
├── 注入说明.txt            面向用户的安装步骤（不含内部信息）
├── 更新说明-v80.md          = docs/56
└── LICENSE
```

### 3.4 发 Release

用 `api.github.com`（这路径是通的）：

```
POST /repos/{owner}/{repo}/releases        建 release（写 tag_name / body）
POST https://uploads.github.com/.../assets?name=xxx   传附件
DELETE /repos/{owner}/{repo}/releases/assets/{id}     删附件（**注意不是嵌套在 release 下**）
```

> 我第一次把 DELETE 写成 `/releases/{rid}/assets/{aid}` → 404。
> 正确端点是 `/releases/assets/{aid}`。

### 3.5 撤设备旧版

```bash
mv FDM.dylib  FDM.dylib.withdrawn-<时间戳>
mv FDM.plist  FDM.plist.withdrawn-<时间戳>
```

**改名停用，不是硬删** —— ElleKit 只认 `FDM.dylib`+`FDM.plist` 这一对，
名字不对就不加载，但文件还在，随时可回滚。

## 四、两条注入路线（现状澄清）

设备上曾同时存在两条路线的文件：

| 位置 | 大小 | 状态 |
|---|---|---|
| `/var/jb/usr/lib/TweakInject/FDM.dylib` | 1.8 MB | **活的**（一直在跑） |
| `App/Frameworks/FDM-troll.dylib` | 1.3 MB · Oct 24 的 v63 | **孤儿** |

**孤儿的判据**（三条都验过）：

1. 主二进制 `strings` 里搜不到 `FDM-troll` / `FDM.dylib` 的 load 痕迹
2. Frameworks 目录下**没有** `CydiaSubstrate.framework`
3. 文件大小停在 v63 时代

⇒ 10-24 那次 TrollFools 注入大概在 App 重装后失效了，之后一直靠 TweakInject 撑着。

**结论**：两条路线不要同时开。TrollFools 重新注入时那个旧文件会被覆盖。

## 五、对外表述收敛

主人：「你这 readme 和发行版太明显了，会被制裁的」

| 位置 | 原来 | 现在 |
|---|---|---|

| README 标题 | `ios-port · FuckDSManger iOS 移植` | `FDM · iOS 运行时模块` |
| README 首段 | 「宿主：DeepSeek Chat · `com.deepseek.chat`」 | 讲技术目标，不点名 |
| 发行标题 | `v80 · 富文本根治 + AI 点歌` | `v80 · iOS 运行时模块` |
| 三方声明 | 「深度求索」 | 「该 App 的所有者」 |
| 包内注入说明 | 点名宿主 | 中性（重打 tar 重传） |
| **二进制** | `FuckDSManger iOS v7.1` ×2 | `FDM iOS` → **0 处** |

### 有一处留着

二进制里 30 处 `DeepSeek_*` —— 那是 **Swift mangled 类名**：

```
_TtC13DeepSeek_Chat16AgentMessageView
DeepSeek_Chat.RootViewController
```

运行时按**字符串匹配类**，改一个字就 hook 不到、功能全废。
⇒ 在「首页不挂靶子」和「功能正常」之间只能保住一个半。

> 顺便：二进制里藏类名本来也没意义（谁下载都能 `strings` 出来），
> 真正的收敛点是**文档门面不点名**，不是让二进制不可读。
