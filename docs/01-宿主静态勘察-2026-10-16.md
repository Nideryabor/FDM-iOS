## 〇、一句话

**iOS 版与安卓版是同一套「服务端下发设置 + 本地覆盖」架构**：同一批键名、同一个
`/api/v0/client/settings` 端点、同一个 `x-settings-token`、同一个 MMKV 库 ——
**但 iOS 侧没有任何 `kv_settings_` 前缀**，且键名不是直接给 MMKV 用的。
⇒ 移植的核心不是"照抄键名"，而是**先定位 iOS 的本地覆盖层在哪**。

## 二、★ 核心证据链

### 2.1 MMKV —— 确认使用 ✅

| 证据 | 位置 |
|---|---|
| `MMKV.framework` 独立打包 | `Frameworks/MMKV.framework` · `com.tencent.MMKV` · **1.3.9** |
| 宿主自研封装（Swift 类） | `_TtC13DeepSeek_Chat13AppMMKVEngine` |
| 配套类型 | `MMKVWrapper` / `AppMMKV` / `PersistEngine` / `Persist` |
| 实例方法 | `mmkvWithID:`（**全二进制仅 1 个调用点：0x10095f6ac**） |
| 默认实例 | `defaultMMKV` |
| 初始化 | `initializeMMKV:logLevel:` |
| 读写选择器 | `stringForKey:`(8 处) / `setString:forKey:` / `setObject:forKey:`(141 处) / `setData:forKey:` / `objectForKey:` / `dataForKey:` / `containsKey:` / `allKeys`(84 处) / `removeValuesForKeys:` |

### 2.2 ⚠️ 关键否证：设置键 **不是** MMKV 的键

- 整个 `__TEXT` 里 **`kv_settings_` / `kv_` 出现 0 次**（只有 `mmkv` 和随机子串）。
- 设置键（如 `optimize_markdown` @0x10095bc74）所在代码 **附近 2500 字节内没有任何 ObjC 调用**（纯 Swift）。
- `stringForKey:` 的 8 个调用点全在 `0x100b7a530 ~ 0x100dc0300`，**远离设置键区（0x10094xxxx~0x10096xxxx）**。

⇒ **结论：iOS 的设置在内存里是 Swift 结构/Dictionary，键名用于 JSON 编解码与字典索引；
本地持久化另有通道（待运行时确认）。**

> ⚡ 这条否证直接否决了"照抄 `kv_settings_<key>` 写 MMKV"的天真移植法。

| 串 | 位置 |
|---|---|
| `https://chat.deepseek.com/api/v0/client/settings` | `__cstring` |
| `https://chat.deepseek.com/api/v0/client/settings/report` | 同上 |
| `x-settings-token` | 与上面两个 URL **紧邻**（同一函数引用） |

⇒ 与安卓抓包报告 §1.4/§1.5 完全对应。**iOS 与安卓很可能共享同一份服务端键表与 version。**
