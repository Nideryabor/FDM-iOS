## 二、⭐ 最有价值的技术发现

### 2.1 宿主架构（静态 + 运行时双证）

```
com.deepseek.chat  2.6.2  MinimumOSVersion=15.0  arm64(thin)

存储：
  mmkv.default              → currentUser / privacy.agree / app.* / app.ab.serverValues
  <用户UUID> 实例            → modelConfig_N / inputConfig / brandProviderConfig / welcomeMsg

服务端下发（59 项，version 93）：
  app.ab.serverValues = 一个 43KB 的「双层 JSON」
    { "version":93, "settings": { "<key>": {"id":N,"value":V} } }

模型配置：
  modelConfig_1 = [ { model_type / name / welcome_msg / prompt_feature
                      / think_feature / search_feature ... } ]
  ⇒ 改这一个 blob 就能动「招呼语 / 回复建议 / 模型名 / 能力开关」4 个功能
```

### 2.2 ⚠️ iOS 与安卓的关键差异

| 维度 | 安卓 | iOS |
|---|---|---|
| 服务端设置落地 | **每键一条** `kv_settings_<key>` | **一整个 blob** `app.ab.serverValues` |
| 混淆 | R8 重命名成 `kh7` / `us6.z` | **无 R8**，Swift 反射元数据保留真名 |
| 协议 | 无 system 通道 | **同样无**（已复核）→ 零宽字符是唯一路 |
| 键前缀 | `kv_settings_` | **不存在**（100% 裸名） |

### 2.3 系统提示词注入（核心功能）

```
协议层结论（iOS 复核）：请求体就只有 10 个字段，
  action / audio_id / chat_session_id / model_type / parent_message_id
  / preempt / prompt / ref_file_ids / search_enabled / thinking_enabled
⇒ 没有 system_prompt 通道 ⇒ 只能借 prompt 侧信道

方案：Unicode Tag 区（U+E0000 + ASCII）拼在 prompt 前
  · 渲染宽度 0（人眼不见）
  · tokenizer 会解回 ASCII（模型能读）
  ⚠️ 只能 ASCII，中文/emoji 编不进
```

**真的在真机上成功了**（`mode=tag`，日志实锤）。

### 2.4 ⭐ 沙盒的硬边界

```
❌ Documents 里 dlopen → "file system sandbox blocked mmap()"
✅ /var/jb/usr/lib 里 dlopen → 成功
```

这是 iOS 的**系统性限制**，不是权限问题。⇒ hot-reload 的 dylib 必须放 `/var/jb/`。

### 2.5 sudo 的能力边界

```
✅ 可写：/var/mobile（App 数据）、/var/jb（越狱环境）、/private/preboot
❌ 只读：/ 、/System、/usr/bin、/System 全族
        （SSV 签名系统卷，硬件级保护，root 也绕不过）
```

⇒ 最坏情况：搞坏 App 数据（重装可恢复），**不可能变砖**。

## 三、💥 踩过的 10 个坑（按代价排序）

| # | 坑 | 症状 | 教训 |
|---|---|---|---|
| **1** | **Hook 太重** | v0.2 崩（登录后 11961 次日志） | Hook 内**只做 O(1) 内存操作**，绝不 IO |
| **2** | **调宿主方法** | `[self mmapID]` 在 MMKV 锁内 → 递归 | Hook 内**只读参数指针** |
| **3** | **Swap 不幂等** | 重复挂 → 原 IMP 指向自己 → **无限递归爆栈** | `Swap` 必须 `if (old == imp) return NULL` |
| **4** | **`HTTPBodyStream = nil`** | 消息发不出去（HTTP 400） | `HTTPBody` / `HTTPBodyStream` **互斥**，后设的赢，**别碰** |
| **5** | **dylib 构造函数碰 Foundation** | 野指针 SIGSEGV | dyld 初始化阶段 ObjC 未就绪 → **只能 dispatch_after 延迟** |
| **6** | **`%@` 传 C 字符串** | `objc_opt_respondsToSelector` 崩 | `LLog(@"%@", "abc")` 是致命的 |
| **7** | **ARC 悬垂指针** | `@autoreleasepool` 内创建，返回后崩 | 跨函数边界的数据必须 **strong 持有** |
| **8** | **Swift 泛型特化类名模糊匹配** | 误 hook 了 Layer/View/Button → 崩 | **必须 `isSubclassOfClass:` 验证真实类型** |
| **9** | **`strncmp(c,"modelConfig",11)`** | 改了 2B 的 Version，漏了 23KB 的 config | 匹配要**精确到数字后缀** |
| **10** | **shell 单引号嵌套** | `sudo sh -c 'cp '$VAR' ...'` 静默失败 | 改用 **stdin 传脚本** |

## 四、🏗 最终架构（hot-reload）

```
┌─ App bundle（TrollFools 管的，已冻结）──────────┐
│  DeepSeek Chat                                  │
│  ├─ LC_LOAD_DYLIB → Frameworks/FDMLoader.dylib  │
│  └─ FDMLoader.dylib   ← 只做一件事：            │
│       dispatch_after(2s) {                      │
│         dlopen("/var/jb/usr/lib/fdm-hot.dylib") │
│       }                                         │
└─────────────────────────────────────────────────┘
                      ↓
┌─ /var/jb/usr/lib/fdm-hot.dylib（尼尼随便换）────┐
│  FLog       日志框架（5 级 + 9 分类 + 崩溃保护） │
│  FDMConfig  配置树（内存缓存 + 已修改追踪）      │
│  FDMFeatures 功能声明（加功能 = 加一行）         │
│  FDMBeauty  UI 美化 hook（背景 / Markdown 样式） │
│  FDMUI      原生设置界面（6 个一级入口）         │
│  FDMProbe   主探针（MMKV 改写 / 网络 hook / 注入）│
└─────────────────────────────────────────────────┘

配置全在 App 的 Documents/*.json（尼尼随时改）
```

## 九、💰 方法论沉淀

### 遇到崩溃怎么查
```
① 拉 crash.ips（SSH 或 WebDAV）
② 解析 faultingThread 的 frames
③ 看前 5 帧里有没有自己的 dylib
④ 有 → 那行代码的锅；没有 → 可能是我改的数据导致了宿主异常
```

### 遇到"功能不生效"怎么查
```
① 看日志有没有"改写了"的记录
   · 没有 → hook 没命中 → 查匹配条件
   · 有但字节数不对（如 23 B 而非 23KB）→ 改错对象了
② 改对了还不生效 → 宿主有缓存 / 渲染层没接 / 服务端数据优先
```

### 加新功能的正确姿势
```
① 在 FDMFeatures.m 加一段 PG(...) 声明（UI/IPC/存储全自动）
② 需要改数据的 → 挂到 FDMApplyModelConfig 或 PatchBlob
③ 需要改 UI 的 → 挂到 FDMBeauty.m
④ deploy.sh 一键部署验证
```
